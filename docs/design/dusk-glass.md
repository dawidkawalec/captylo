# Dusk Glass (Deep Tide)

The design language of Captylo. Binding for every window, panel and control: the product owner rejected the plain system look, and the app must look like the mockups in this folder. Since Brand Direction 01 (2026-09-27) it wears the **Deep Tide** palette, the animated **Grainient** background and **Manrope + Inter** type; the shapes of the mockups (panels, rows, rims, widget) still hold, their violet dusk colours do not. The brand kit is `branding/direction-01/`; the owner's picks were made in the HTML labs `docs/design/lab/brand` (gradient, palette, glass, dimming) and `docs/design/lab/pulpit` (Pulpit layouts). Before any UI work, open the mockups:

| Mockup | What it defines |
|---|---|
| `01-widget-compact-horizontal.png` | THE compact widget: glass orb + free-floating waveform + timer, no container |
| `02-widget-compact-vertical.png` | Same elements stacked (orb over the waveform) |
| `03-widget-expanded-on-wallpaper.png` | THE reference for every card, panel, row, toggle and button in the whole app |
| `04-widget-expanded-isolated.png` | The expanded widget without the wallpaper (shapes and rims) |

The living catalog of the components is the `glass-gallery` preview target (see "Design preview" below): the left column rebuilds the lower panel of mockup 03 from the components.

## Principles

1. **The window background is the user's pick ("Tło okna").** Every window (onboarding, main window, sheets, previews) is full bleed `DuskBackground`, drawn in the `WindowBackgroundStyle` chosen in Ustawienia > Wygląd (`AppSettings.windowBackground`, key `ui.windowBackground`, default `.captylo` "Ciemny", the owner's pick; switches live; only an explicit choice is stored, so whoever never picked follows the default). Picker order: Ciemny, Jasny, Zmierzch, Gradient. The style travels as the environment value `windowBackgroundStyle`, set at the root of the main window and the onboarding and inherited by sheets; outside those windows (the recorder widget) it is nil and nothing changes. The see-through "Szkło" style was removed at the owner's request: a stored `"glass"` no longer parses and falls back to the default, and every window is opaque.
   - **Ciemny (`.captylo`, `GrainientBackdrop`, the default)** and **Jasny (`.captyloLight`)**: React Bits "Grainient" ported to Metal (`Grainient.metal`, one full-screen triangle, `precise::sin` in the hashes so the grain matches WebGL), drawn by an `MTKView` (`GrainientMetalView`, shared pipeline in `GrainientRenderer`) at `renderScale` 1.5 at most, 60 fps. Parameters are the owner's from the lab (`GlassTokens.Grainient`: timeSpeed 1.05, warpFrequency 5.4, warpSpeed 1.5, warpAmplitude 50, blendAngle -2, blendSoftness 0.08, rotationAmount 500, noiseScale 1.65, grain 0.09 at scale 2 (static), zoom 0.95). Palettes: `dark` = Abyss #10272C, Petrol #214A52, Glacier #9FE6DC, contrast 1.5; `light` = Fog #B7CCCB, Petrol, Glacier, contrast 1.15, gamma 1.05. It animates only while the window is key in the active app and Reduce Motion is off; otherwise it holds the current frame. sRGB colour space. Without Metal a static gradient in the same colours is drawn. Black scrim `Scrim.grainient` (window and onboarding 0.10, the owner's "Przyciemnienie tła", sheets 0.2) and `Scrim.grainientLight` (0.16 / 0.24).
   - **Gradient (`.aurora`, `AuroraBackdrop`)**: a slow dusk sky in the brand palette (night, navy, indigo, violet, orchid, rose, peach, horizon glow), dark on top, warm low in the window. Three compositions (`AuroraSky`: 4 x 4 `MeshGradient` on macOS 15+, drifting radial glows on macOS 14) are rendered once into 480 x 320 bitmaps (`AuroraFrames`), and Core Animation cross-fades them over `Aurora.period` (30 s) while each layer drifts on an ellipse and breathes at its own longer period (`AuroraLayerHostView`). The motion runs in the render server: 0.0-0.1 % app CPU while animating (a SwiftUI `TimelineView` cost about 6 % at any frame rate, the `.animation` schedule keeps a display link at screen rate). Paused (layer speed 0, resumes where it stopped) while the window is not key or the app is inactive; Reduce Motion shows the first composition still. Black scrim `Scrim.aurora` (window 0.16) darker under the titles, plus the vignette. The window is opaque night.
   - **Zmierzch (`.dusk`, `DuskPhotoBackdrop`)**: the pre-Deep Tide look, alive. A calm seamless video loop of our own blurred dusk photo (`Resources/Video/dusk-loop.mp4`, no stock footage) plays over the photo (asset `DuskWallpaper`, source copy in `docs/design/backdrops/dusk-wallpaper.jpg`), which is the poster until the first frame is ready (0.6 s cross-fade) and the fallback. Both sit under a night scrim heavier at the top (`Scrim.dusk`: window 0.34, onboarding 0.25, sheets 0.4) and a vignette. The window is opaque night.
     - **The loop** (`scripts/make-dusk-video.sh`, reproducible): 24 s, 1920 x 1200, 30 fps, 10-bit HEVC (`hvc1`, Main 10), no audio, about 1.3 MB. Every motion is a whole number of cycles per loop, so the frame after the last is the first: a Ken Burns breathe (scale 1.02 -> 1.07 -> 1.02) with a slow elliptic drift, the lake reflections rippling below the horizon (travelling sine displacement whose phase bends along x, faint broken glints, smooth ramp from 57 % of the height), and a warm glow over the sun and its reflection breathing twice per loop. One bilinear `geq` pass at 960 x 600, upscaled (the photo is blurred, nothing is lost), I/P/B frames at equal quality so the seam matches any other keyframe. `STILL=<png> STILL_T=<s>` renders one frame for tuning, `PREVIEW=1` 2 s.
     - **Playback** (`DuskVideoView`): `AVPlayerLayer` in an `NSViewRepresentable`, `AVQueuePlayer` + `AVPlayerLooper`, muted, `resizeAspectFill`, never prevents display sleep, one player per window (the window's single `DuskBackground` owns it, torn down in `dismantleNSView`). Plays only while the window is key in the active app (`controlActiveState == .key`), on screen (`NSWindow.occlusionState`, not minimized) and Reduce Motion is off; otherwise it pauses on the current frame. Cost: about 0.7 % app CPU plus 0.5 % in `VTDecoderXPCService` (hardware decode) on the design preview.

   Transparent title bar, content drawn edge to edge, dark color scheme forced so system controls render light on glass; one modifier does all of it: `.duskWindow(role:)` (`WindowBackdropRole`: `.window`, `.onboarding`, `.sheet` picks the scrim). Reduce Transparency: solid night (Abyss) in every style.

   **Tone ("Przyciemnienie tła", "Przydymienie paneli").** Two sliders under "Tło okna" (`AppSettings.backgroundDim` 0-40 %, default 10, key `ui.backgroundDim`; `AppSettings.panelSmoke` 0-50 %, default 20, key `ui.panelSmoke`) reach every window as the environment value `windowTone` (`WindowTone`, set next to `windowBackgroundStyle`; the widget keeps `.standard`). The dim shifts the scrim of every style by its difference from 10 % (`WindowTone.scrim(_:)`, clamped to 0-0.9), so the per-style scrims above are the values at the default. The smoke is the Abyss wash inside every frosted panel and, on top of the sidebar's own 0.2 tint, of the sidebar. The owner wants the same ~10 % darkening kept on the website and other brand materials.
2. **Surfaces are clear frosted glass** ("Czyste" in the lab), the same over every window background: translucent (the gradient shows through), a light white wash (`glassTint` 0.10, `glassTintClear` 0.06) plus the Abyss smoke from `windowTone`, 1 pt luminous rim brighter at the top, large continuous corners (28 pt panels, 18 pt inner cards, capsules for pills), soft shadow, generous padding. Not the milky white card with dark text and not the filled accent pill from the brand board (both rejected). macOS 26: SwiftUI Liquid Glass (`glassEffect`, `Glass.clear`, tints). macOS 14/15: `.ultraThinMaterial` + white fill + smoke + gradient rim. Both paths are inside `glassSurface`, never re-implemented in a view.
3. **Glass never sits on glass.** Only the outermost surface (`GlassPanel`, stat tiles, the sidebar, the widget header) is real glass. Anything inside a panel (cards, buttons, tracks, badges) is a plain translucent fill with a rim. Nested glass samples glass and turns muddy.
4. **White type on glass.** Inter for UI and body (Regular / Medium / SemiBold), Manrope for titles and numbers (SemiBold headings, Bold stat values, ExtraBold hero number), always through `GlassFont`, never `.system` in a screen. The fonts ship as static TTF instances in `Resources/Fonts` (SIL OFL, licences next to them) and register through `ATSApplicationFontsPath` in `project.yml`. Primary white 95 %, secondary white 70 %, tertiary 50 %. Section titles Manrope SemiBold 15 pt with a thin line icon on the left. Numbers use monospaced digits. No black text on these surfaces, ever.
5. **Rows like the mockup.** Outline SF Symbol + label on the left, value + chevron on the right, hairline white 12 % separators between groups (not between every row). Toggles are the Tide switch. Buttons: neutral glass ("Pauza"), destructive Record-red glass with glow ("Zakończ"), accent Tide glass for the primary action of a screen.
6. **Calm motion.** Gentle springs, glass morphing between states on macOS 26 (`glassEffectID` inside a `GlassEffectContainer`). Reduce Motion: no slides or scale, cross-fades only. Reduce Transparency: solid dusk fills (`GlassColor.solidPanel` / `solidCard`) with the same rims, handled by `glassSurface`.
7. **Brand.** Captylo, Brand Direction 01 variant B: the heavy round C with the wider diagonal cut and the custom lowercase "captylo" wordmark (assets `AppIcon`, `BrandSymbol`, `BrandWordmark`, `MenuBarIcon`, `MenuBarIconRecording`; vector sources generated by `branding/direction-01/brand.py`). Deep Tide colours live in `VTColor`: Abyss #10272C, Petrol #214A52, Glacier #9FE6DC, Fog #B7CCCB, Salt #F2F7F4, Record #F27878, and the derived accent Tide #2F8F88 (fills, switches, the accent button; the app icon also uses #2A8581). The old names map onto them (`brandViolet` -> tide, `brandPink` -> fog, `brandOrange` -> glacier, `brandNight` -> abyss, `brandIndigo` -> petrol, `recordRed` -> record). Record red only signals live recording.

Rules of thumb:

- Never write `.background(.ultraThinMaterial)`, `glassEffect` or hex colors in a screen: use `glassSurface` / a component / a token. Add a token when something is missing.
- Never put a `GlassPanel` inside a `GlassPanel`. Inside a panel use `GlassCard`, rows and separators.
- One accent button per screen at most; destructive only for stopping, deleting and discarding.
- `List`, `Form` and `Table` backgrounds must be hidden (`.scrollContentBackground(.hidden)`) and restyled with rows on glass; the system grouped look breaks the language.

## The recorder widget

- **Compact (mockup 01).** A modest frosted glass orb (`RecorderMetrics.compactOrb` 46 pt, smaller than the mockup's 64 at the owner's request; Liquid Glass bubble with a bright rim and an inner highlight) holding a white mic glyph (0.42 of the orb), the glowing red dot at its upper right (about 5 pt), then a free-floating row of 15 white rounded waveform bars (72 x 28 pt, center tallest, soft white glow), then the timer "00:18" in `GlassFont.number(13)`. The orb's own shadow is a soft low lift (black 0.13, radius 6). NO rectangular bar or container behind them. For legibility over bright content the marks carry the tight `glassFloatingHalo()` outline, and the waveform, the timer and the status line share ONE soft dark cloud, `RecorderBackdropHalo`: a single blurred black capsule over the union of the visible marks (`RecorderMetrics.compactHaloRect`: waveform + timer while recording, waveform + status lines while processing, animated between them), peak `backdropOpacity` 0.42, spread 18 x 16 (8 on the orb side), blur 16. It has no visible edge and is nearly invisible over a dark desktop; over a white window it leaves a grey bed around 180 under the timer. Never two clouds (the old per-mark clouds read as two dark smudges on white), never a box. The canvas `margin` (72) leaves room for its feathered tail under the two-line processing status. While recording or paused with AI on and a rewrite mode active ("Po angielsku", "E-mail"...), the status slot names the mode with its symbol (`RecorderModel.compactStatusDetail` / `compactStatusSymbol`), so the owner knows before stopping that the take will not paste as dictated; the cleanup mode stays silent (mockup 01). Preview: `widget-compact-mode`. Check it over white as well as over a dark and a colorful backdrop (`SNAP_BACKDROP=white|dark|dusk`).
- **Expanded (mockups 03 / 04).** Header glass capsule (the 64 pt orb, `OrbButton(size:)` defaults to it, + waveform + timer + status line "Nagrywanie... mów swobodnie"), below it a `GlassPanel` with the "Transkrypcja na żywo" `GlassCard` (live text bottom-anchored with a top fade), rows "Mikrofon" (current device, menu to pick), "Język transkrypcji" (menu) and "Tryb AI" (sparkles; menu with "Bez AI" and every AI mode, checkmark on the active one, then "Edytuj tryby..." which opens Modele; the controller reads the mode when the take stops, so a pick applies to the running take), toggles "Automatycznie kopiuj transkrypcję" and "Zapisz transkrypcję po zakończeniu", and the buttons "Pauza" (`.glass(.neutral, fillsWidth: true)`) and "Zakończ" (`.glass(.destructive, fillsWidth: true)`).
- **Hover.** The widget expands while the pointer is over it and collapses when it leaves, with a smooth morph (`glassEffectID` in a `GlassEffectContainer` on macOS 26, spring resize below). State: `RecorderModel.isExpanded`; `RecorderModel.isExpansionPinned` keeps it open (the `widget-expanded` preview).
- **Processing** (Transkrybuję, Poprawiam z AI): the orb with a subtle spinner or shimmer, a calm low waveform, the status line. While AI runs the line names the mode: "Poprawiam z AI · Uporządkuj myśli" (`RecorderModel.enhancingModeName`, taken when the phase turns `.enhancing`; `widget-enhancing` preview).
- **Waveform shape.** `WaveformMath` puts every bar under a gaussian bell (`exp(-(d / (count * w))^2)`, `w` 0.16 for the 15 compact bars, 0.22 for the 25 header bars): dots at the ends, in the compact widget only the center 3-5 bars tall. Compact bars are 2 pt wide with 3 pt gaps (airy, not a comb). While recording the bell never drops below `recordingFloor` (0.35) of its height, so quiet speech still shows the mockup shape; the travelling wave only moves the part above the floor. The design preview freezes one frame at the crest (`RecorderModel.isWaveformStill`, level 0.85).
- **Widget glass (macOS 26).** Glass wraps the content itself (`glassEffect` on the clipped content, a white 0.20 wash inside): inside a `GlassEffectContainer` glass on a background layer is composited above the content. The widget keeps the dark regular glass, because it floats over white documents where light glass would make its white type unreadable; the 0.20 wash lifts it to the milky mid grey of mockup 04 (about 133 over a white window) and a soft lift over a dark or colorful desktop. Marks with no surface behind them (compact timer, status line, waveform, mic glyph) carry `glassFloatingHalo()`. `screencapture -l` has no backdrop, so it shows the glass as flat grey with squared inner layers that do not exist on screen: not evidence for the widget glass. Judge it from a region capture over a real backdrop (`SNAP_BACKDROP=white|dark|dusk scripts/snap.sh widget-compact out.png`).
- The panel never activates the app (`orderFrontRegardless`, `canBecomeKey = false`), see `docs/architecture.md`.

### Main window

- `.duskWindow()` on the root; the sidebar and the detail share one window glass, no system sidebar material and no divider.
- **Sidebar (`MainSidebar`, the owner's pick #38 in the Pulpit lab):** attached to the left window edge from top to bottom (`MainShellMetrics.sidebarWidth` 228, no insets, no corner radius): `.ultraThinMaterial` washed with Abyss (`sidebarInkWash` 0.2 + the panel smoke) and a white 14 % hairline on its right edge. On top the white `BrandWordmark` (28 pt high), then the seven sections as rows (Inter icon + title, white 78 %, selected SemiBold white). The selected item is a white 20 % capsule with a rim that slides with `GlassMotion.selection`. At the bottom the support card, version and captylo.com.
- **Content:** page title in `GlassFont.pageTitle` at the top left, then `GlassPanel`s in a scroll view with 20-24 pt gaps. Banners (Dostępność, stara wersja, model) are slim panels with an orange `GlassIconBadge` and small glass buttons.
- **Shell contract (`MainView`):** the shell draws the page title (`MainPageHeader`) and the banners for every section, so a screen never adds its own title. Screens scroll inside `MainGlassPage { ... }` (no background, column gutters, readable max width 960, soft top fade under the header, soft bottom fade); custom layouts use `.mainColumnFrame()` and `.mainEdgeFade()` (top and bottom fade) from `MainGlassPage.swift`. ## Design preview

`--design-preview <target>` shows one screen on fake data and nothing else: no hotkey tap, no audio engine, no model load, an in-memory store with 42 dictations over 14 days, a temp `dictionary.json`, the defaults suite `com.captylo.app.design-preview` (wiped at start), a seeded key store, Parakeet "ready", a fixed OpenRouter list, and no menu bar item. It prints `WINDOW_FRAME=x,y,w,h` (screen points, origin top left of the main display, for `screencapture -R`) and `WINDOW_ID=<n>` once the window is on screen and runs until killed. With `CAPTYLO_PREVIEW_BACKDROP=white|dark|<image path>` it first puts a plain borderless window right behind the target, so the window glass and the widget show over a known backdrop; both float above other apps' windows while the preview runs, so the capture is never covered. `CAPTYLO_WINDOW_BG=captylo|captyloLight|aurora|dusk` picks the window background ("Tło okna") of the preview. `CAPTYLO_PREVIEW_SIZE=<w>x<h>` makes the main window taller or wider to capture long pages (Słownik with "Nauczone" and "Twój styl"); the design preview also writes a sample `learning.json` next to its temp dictionary. It is safe to run next to a real Captylo, never activates the app and never writes the real defaults domain or data folder.

Targets: `widget-compact`, `widget-compact-mode`, `widget-expanded`, `widget-transcribing`, `widget-enhancing`, `onboarding-welcome`, `onboarding-permissions`, `onboarding-model`, `onboarding-shortcut`, `onboarding-tryit`, `main-pulpit`, `main-spotkania`, `main-historia`, `main-plik`, `main-slownik`, `main-modele`, `main-ustawienia`, `glass-gallery` (`scripts/snap.sh --list`).

```bash
make build
scripts/snap.sh main-pulpit /tmp/pulpit.png                        # window over the real desktop
SNAP_BACKDROP=dusk scripts/snap.sh main-pulpit /tmp/pulpit-dusk.png  # over docs/design/backdrops/dusk-wallpaper.jpg
SNAP_BACKDROP=white scripts/snap.sh widget-compact /tmp/w-white.png  # widget over white (also dark, dusk, an image path)
CAPTYLO_GLASS_FALLBACK=1 scripts/snap.sh glass-gallery /tmp/g.png  # macOS 14/15 material path
CAPTYLO_WINDOW_BG=captyloLight SNAP_BACKDROP=dark scripts/snap.sh main-pulpit /tmp/jasny.png  # "Jasny"
CAPTYLO_WINDOW_BG=aurora SNAP_SETTLE=12 scripts/snap.sh main-pulpit /tmp/aurora-12s.png        # a later aurora frame
```

Use `SNAP_BACKDROP=dark` for main-window captures: the window is opaque, but without a backdrop window the region capture can pick up whatever else is on screen while the preview comes up.

`snap.sh` launches the Debug binary, waits up to 20 s for `WINDOW_ID`, waits `SNAP_SETTLE` (2.5 s) for animations, captures, kills exactly that process and exits non-zero on failure. Windows are frosted glass over whatever is behind them, so they are always captured as a screen region (`screencapture -R` of `WINDOW_FRAME`); a window capture (`-l`) has no backdrop and shows no blur. Widget targets without `SNAP_BACKDROP` use `-l` (transparent around the widget, window shadow kept); with it, a region capture over the backdrop, which is the real evidence for the widget glass and the halo.

Never launch the Debug app without `--design-preview` (a plain launch or `--open-section` starts a second hotkey tap and every take is typed twice), and never `pkill` / `killall Captylo`: kill only the PID you started.
