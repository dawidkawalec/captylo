# Architecture

Captylo is a single macOS app target plus a unit-test target. Everything is built from `project.yml` with XcodeGen. The old app it replaces (a VoiceInk fork) is only a reference: its behaviour was mapped into port notes that the owner keeps outside this repo. This file records the decisions that override them.

**Open core.** The app is public; the service behind Pro (`api.captylo.com`: accounts, payments, the relay, Captylo AI) is private and not in this repo. The app only knows its HTTP contract: `AccountClient` (account, billing) and the relay routes (`CloudRouter`). The meeting AI runs as "Captylo AI": the app sends the data as the user message plus a `CaptyloAITask` (`captylo_task: { kind, template? }`, kinds `meeting_notes`, `meeting_ask`, `library_ask`, `transcript_correction`) and the relay adds its own instructions, picks the model and answers with `model: "captylo-ai"`. History and logs keep `captylo-ai` (`Enhancer.relayModelPlaceholder`); the UI shows "Captylo AI" (`Enhancer.displayName(forModel:)`).

## Decisions (override the brief where they differ)

| Topic | Decision |
|---|---|
| Deployment target | macOS 14.4, arm64. Liquid Glass behind `#available(macOS 26, *)`, `.ultraThinMaterial` + 0.5 pt white stroke fallback. No `Synchronization` module (needs 15): use `OSAllocatedUnfairLock` for shared mutable state on audio paths. |
| Speech engines | Local Whisper large-v3-turbo via WhisperKit 1.1.0 (argmax-oss-swift, MIT; variant `openai_whisper-large-v3-v20240930`, full precision, ~1.6 GB in `<data>/WhisperModels`, Core ML on the Neural Engine; default) and ElevenLabs `scribe_v2` (cloud). Nothing else. Cloud failure falls back to the local model when it is installed. Live preview always uses the local model. Chosen on 2026-10-02 over Parakeet TDT 0.6b v3 after a benchmark on a real 15 min Polish meeting through the meeting pipeline: WER against the cloud 31.4 % vs 37.7 %, substituted words 105 vs 152, English/Spanish insertions on backchannels 0 vs 66 (Parakeet cannot be forced to Polish; Whisper takes the language code). Decoding: language forced, no first-token log-prob threshold (a low first token ends the segment empty and leaves it to the random temperature fallback; utterances cut mid-sentence vanished), no no-speech skip on final passes (the audio is known to hold speech; a near-silent dictation that comes back as only "Dziękuję." / "Thank you." is dropped by `TranscriptionRouter.filterHallucination`), WhisperKit's other thresholds as shipped. Deleting the model goes through `WhisperEngine.deleteModel()`, which refuses new loads, waits for a running load and pass, then unloads and removes the files. The 626 MB palettized variant lost (131 vs 109 substitutions), Cohere Transcribe hallucinated on silence. FluidAudio 0.17.4 stays for the meeting VAD and diarization; earlier versions' Parakeet folder is only offered for removal in Modele. |

| Self-learning | Local only, no server (Honcho and similar were rejected: privacy and the Free plan). Switch `learning.enabled` ("Ucz się z moich poprawek", default on). Sources: words spelled out loud (`SpellingDetector`, before `TextProcessor`; a take that is only a spelling, "Pisane J-E-V", is not pasted and corrects the closest word of the previous take) and edits of pasted text read back through Accessibility (`EditWatcher`: only the pasted field, polled twice a second; when our text leaves the field (a chat message sent, the box cleared) the watch ends with the last text that still held it; ends when the field loses focus (its own `AXFocused` first) or the app changes, on the next take, 90 s idle or 10 min; never secure fields, password managers or terminals; `start()` calls `prepare()`, which sets `AXManualAccessibility` on the frontmost app and, for Chrome-family browsers, `AXEnhancedUserInterface`, so the tree is built by paste time; every AX call runs off the main actor behind a deadline (`EditWatcher.offMain`: 150 ms for the snapshot before Cmd+V, else no watch; 2 s while watching) on top of a 0.5 s AX messaging timeout; browser results in docs/reference/ax-coverage.md). `CorrectionLearner` (pure) keeps 1...3-word term fixes, sends bigger edits to style samples and drops rewrites (< 50 % words kept) and text typed after the paste. A pair is learned at the first sighting (the owner's workflow: select the word, retype it, done; `SelfLearning.threshold` = 1, the Cofnij toast is the safety net): the correct form joins the vocabulary, and a replacement rule is added only when the misheard side is not a real word (`NSSpellChecker` pl + en), otherwise it is an AI hint. Every lesson shows "Zapamiętałem: a → B [Cofnij]"; undo removes what it added and blocks the pair; correcting a learned form back drops the rule, twice forgets it. Style: every 8 samples the utility enhancer (15 s, only with AI on) distills a profile of at most 700 characters, editable in Słownik; the prompt gets the hints, the profile and the target app name. Memory in `learning.json` next to the dictionary (so test host and design preview use temp copies). Settings also hold `learning.notifications` (the toasts) and `learning.excludedApps` (bundle ids picked as .app in Ustawienia > Nauka, on top of the built-in list). Every watched paste, edited or not, adds to daily `editStats`; Pulpit shows "Poprawki/100 słów" over 14 days once there are 50 watched words. The vocabulary does not reach the local model: a Whisper prompt with the vocabulary (3 or 11 terms) fixed one surname on the owner's meeting but dropped 2-3 times more words (168-209 deletions vs 63) and ran slower, so the local model gets no prompt and replacement rules stay the way to fix its spelling. |
| Updates | Sparkle 2.9.4 (Swift package, MIT, `NOTICE.md`), standard user driver (its own windows, Polish from Sparkle's `pl.lproj`), EdDSA-signed appcast at `SUFeedURL` = `https://captylo.com/updates/appcast.xml`, automatic checks on by default (`SUEnableAutomaticChecks`, daily), switchable in Ustawienia > Aplikacja > "Sprawdzaj automatycznie". Debug builds accept `CAPTYLO_APPCAST_URL` as a local feed (the tampered-update test); release builds ignore it. `CFBundleVersion` is the build number Sparkle compares. |
| Dependencies | FluidAudio, WhisperKit and Sparkle (updates, see "Updates"). A system library needs no `NOTICE.md` entry. |

Ownership rule: a module talks to another only through the protocols in `Dictation/DictationTypes.swift` and the concrete types listed in the brief section 4. `AppState` builds every service once in `init` (safe for the headless debug commands) and injects them; `startServices()` adds the launch behaviour of a GUI run (tap install on the Accessibility grant, audio and local model prewarm, the meeting voice detector prewarm, retention, the calendar refresh loop and reminders, call detection, settings observers, the Sparkle updater). No singletons except `Log`. Shell hooks the controller needs (open Modele, open a Settings pane, bump stats) are closures in `DictationEnvironment`, so `Dictation/` never imports the window layer. `AppState` also owns the `FileTranscriptionQueue`: Finder "Otwórz za pomocą" files are stashed in `pendingOpenURLs` until `startServices()` has created the data directories, then fed to the queue and the main window opens on Transkrypcja pliku; the drop zone feeds the same queue. `AudioDecoder` accepts wav, mp3, m4a, aiff, aac, flac, caf, mp4, mov and Ogg/Opus voice notes (ogg, opus, oga); a file without a known name extension (messenger voice notes saved as `voice_<date>`) is recognised by its first 12 bytes (`sniffedExtension`). `AVAssetReader` decodes first; Ogg goes straight to `AVAudioFile` + `AVAudioConverter`, since `AVURLAsset` cannot open it, and the same path is the fallback when `AVAssetReader` fails. Ogg relies on Core Audio (verified on macOS 26); where the system cannot read it the row says "Ten format nie jest obsługiwany przez macOS na tym komputerze." The picker also allows `.data` so extensionless files can be chosen; Finder "Otwórz za pomocą" is registered for audio, movie and the Ogg types only.

## Dictation flow

1. `HotkeyTap` (background thread) → `HotkeyController` (MainActor) decides tap vs hold → `DictationController.start()`.
2. `start()`: mic permission check, device resolve, `AudioCapture.start` (samples into `SampleBuffer`, WAV to disk), after 150 ms play the start sound, show the widget, mute system output; `LivePreview` re-transcribes the last 15 s every 1.5 s while recording (a Whisper pass takes 0.7-0.9 s; a preview never waits for the model and stops decoding as soon as a final pass is waiting).
3. `stop()`: stop capture, `TranscriptionRouter` (local Whisper full pass or ElevenLabs upload with the local fallback), `SpellingDetector` (words spelled out loud), `TextProcessor` (tags, fillers, whitespace, paragraphs, replacements), optional `Enhancer` (OpenRouter, 3 s deadline, prompt with the learned hints and style), stop sound, hide widget, `EditWatcher.willPaste`, `TextOutput.deliver` (pasteboard + Cmd+V + restore), `EditWatcher.didPaste`, then `Database.save`, bump `statsVersion` and learn the spelled words. `start()` of the next take flushes the watcher first.
4. `cancel()` (Esc twice, or accidental-start guard) aborts capture, deletes the WAV, hides the widget, saves nothing.

Timing budget on Apple Silicon: key-up to paste <= 400 ms local; with AI cleanup p50 ~1 s, never more than deadline + 0.3 s.

## Spotkania (notetaker)

Records a call on the Mac without a bot: the mic as "Ja" and everything the Mac plays as "Rozmówcy", two separate tracks, transcribed live and locally with the Whisper model. Separate from the dictation path: the dictation hotkey keeps working during a meeting and both transcripts land.

**Layout.** Logic in `Captylo/Meetings/` (recorder, transcriber, feeds, echo filter, export, retention, launch resume, `ProAccess`), with `Audio/` (sources, track files, watchdog, Core Audio process list, voice processing), `Speakers/` (diarization), `AI/` (templates, notes and "Zapytaj"), `Search/` (the full-text index and the search results), `MCP/` (the read-only MCP server), `Detection/` (call detection) and `Calendar/` (the user's calendar, matching, reminders). Views in `Captylo/UI/Meetings/` (sidebar section "Spotkania": the "Nadchodzące" strip, "Połącz kalendarz" while the calendar is off and not dismissed, or on while macOS has not answered (`CalendarConnectRow`; "Nie teraz" turns the calendar off and sets `meetings.calendarPromptDismissed`; with the calendar on but no full access it explains why and opens System Settings; the text and a line under "Kalendarz" in Ustawienia point Google and Outlook users to macOS Internet Accounts, `CalendarAccess.openInternetAccounts()`, since EventKit reads every account added there), search with hit lines, list, live view, details with "Notatki", "Transkrypt", "Notatki AI" and "Zapytaj", the "Zapytaj wszystkie spotkania" panel, settings panel). Storage in `Data/MeetingModels.swift` (`Meeting`, `MeetingSegment`) and `Data/Database+Meetings.swift`. One type per file; tests in `CaptyloTests/Meeting*Tests.swift` with fakes in `MeetingFakes.swift`.

**Data flow.**

1. `MeetingRecorder` (`@MainActor @Observable`, one meeting at a time) refuses to start without the speech model on disk (`MeetingEnvironment.speechModelReady`: every pass would fail and the meeting would end with no transcript; Spotkania shows "Brakuje modelu mowy" with "Otwórz Modele"), then creates the `Meeting` row (`start(title:appName:event:)`: an explicit event, or with no title the event `MeetingEnvironment.currentEvent()` matches now, gives the title, `calendarEventID`, `participants` and the app name from its call link; a default "Spotkanie w Zoom, ..." title only without an event), suppresses `SystemMute` for the whole meeting (a dictation take never mutes the call) and starts the sources on its own serial queue: `MeetingMicCapture` (default input on its own `AVAudioEngine`, rebuilt on device changes, holes filled with silence; `MeetingEnvironment.makeMic` runs on the main actor at start, so it reads "Redukcja echa" then) first, then `SystemAudioTap` (global Core Audio process tap excluding Captylo, private aggregate device, converted to 16 kHz mono Float32). "Nagraj spotkanie" (menu bar, Spotkania, the detector) always opens Spotkania first: a meeting never records without its live bar and the menu bar state.
2. Each source feeds a `MeetingTrackFeed`, which keeps the track on the meeting clock (pads the start and rebuild holes) and hands every buffer, under one lock, to a `TrackFileWriter` (`me.caf` / `them.caf`, 16 kHz mono Int16, appended as recorded) and to the `MeetingTranscriber` actor.
3. `MeetingTranscriber`: per track, 4096-sample chunks -> Silero VAD (shared `SpeechDetectorCache`) -> utterances of at most 14 s (28 s was tried: longer mic utterances mixed the user's words with echo of the other side, the segment-level echo check dropped them, and Whisper substituted more words too) -> timed Whisper pass (word times, `WordTimings`) -> `MeetingSegment` saved right away. Partials go through `previewText`, which returns "" while the model is busy, so they never hold up a final. Partials (the grey line) about once per second of speech. Memory per track is one open utterance, never the whole meeting. When the VAD cannot load or a pass throws (no or a broken model), the transcriber sends `MeetingLiveUpdate.problem` and the live bar warns that no transcript is being made until it works again. The VAD (about 1 MB, downloaded once by FluidAudio) is fetched ahead of the first meeting: `SpeechDetectorStatus` (`AppState.speechDetectorStatus`, states missing / loading / ready / failed) calls `SpeechDetectorCache.prewarm()` after a successful local model download (`LocalModelStore.onDownloaded`) and in `startServices()` after the local model prewarm when the model is installed; Modele and the onboarding model step show it under the model status as `SpeechDetectorStatusLine` ("Wykrywanie mowy do spotkań: gotowe" / "pobieram..." / "nie pobrano (...)", nothing while missing). A failure is only logged and shown there; a meeting started meanwhile loads the detector itself.
4. `stop()` closes the sources and files, `finish()` marks echo between the tracks (`EchoFilter`), the row gets its length and goes to "processing", and the recorder is idle again (a back-to-back call can be recorded at once; the detector asks about a call that started while the last meeting finished once the recorder is idle). The post-processors (`MeetingPostProcessing`) then run in the background, one meeting at a time in stop order: `MeetingCloudTranscription` (Pro, "Dokładniejszy transkrypt z chmury"), `SpeakerLabelProcessor` (Pro, macOS 15+), `MeetingCorrectionProcessor` (Pro, "Poprawiaj transkrypt przez AI"), `MeetingNotesProcessor` (AI notes, Pro), `MeetingRetention` (last, it may delete the audio the first ones read). Then "completed" and `processedCount` bumps, so Spotkania reloads the labels and the notes. Meanwhile the list says "Przetwarzam" and "Notatki AI" says "Piszę notatki...".
5. Crash or quit: segments saved so far stay, the CAF files stay readable (`abortForTermination` closes them on a normal quit); `recoverInterruptedMeetings()` marks the row "Przerwane" at the next launch, marks its echo (the stop never did) and gives it a length (the longer of the track files and the last segment). A quit while the post-processors still run leaves the row "processing": the transcript, echo marks and length were saved by the stop, only the extras were cut. `Database.markInterruptedMeetings` returns a `MeetingRecovery` (`interrupted` plus `resumed`, the "processing" rows marked "completed" in stop order) and `resumeProcessing(ids:)` queues `MeetingEnvironment.resumeProcessors` on the same serial chain as a stop, with `reopen`: the row reads "processing" again, then "completed" and `processedCount` bumps. The resume list holds only the AI steps, each behind a `MeetingResumeStep` that skips work already on the row (`MeetingCorrectionProcessor` when `transcriptAIModel` is nil, `MeetingNotesProcessor` when `summary` is nil; their own Pro and setting gates still apply), then `MeetingRetention`; never the cloud pass and never the diarizer (a crash there must not repeat at every launch). A crash during the resume leaves finished steps done, so the next launch runs only what is still missing. "Napisz notatki" and "Popraw" keep working on an interrupted row.

After audio: quiet tap rebuilds (30 s, 30 s, 60 s, then every 120 s of zeros) and a gap ("przerwa w nagraniu") when a rebuild brought the audio back. Ustawienia > Spotkania > "Sprawdź" runs the tap for 2 s (`SystemAudioCheck`). The headphones hint shows while the default output is the built-in speakers.

**AI notes (Pro).** `MeetingSummarizer` sends one non-streaming request over the whole transcript (a 1 h meeting is about 20-25k tokens) as a `CaptyloAITask` (`meeting_notes` with the template id) on `HTTP.meetingLLMSession` (150 s idle, 180 s total), always on the Pro relay (`CloudRouter.relayAIRoute`; an own AI key never counts here). Citations `[mm:ss]` play the track at that moment.

**Cloud transcript (Pro).** `MeetingCloudTranscription` (`Meetings/Cloud/`) re-encodes each track as AAC in an `.m4a` (`TrackUploadEncoder`, about 15 MB per hour; WAV if the encoder is missing), sends it to ElevenLabs Scribe with word times (`ElevenLabsSTT.transcribeWords`, the user's cloud key or the Pro relay, the transcription language and the dictionary as keyterms) and turns the words into segments (`CloudTranscriptSegments`: a new one after a 1 s pause, at a sentence end from 14 s, always at 25 s). Each track's segments replace its live ones (`Database.replaceSegments`), echo is marked again, and the row names the model (`transcriptModel`). A track that fails, or comes back empty where the live pass heard speech, keeps its live lines; the reason goes to `transcriptError`. Both tracks are sent (the mic track too: it is where the user's own names and terms get misheard), but only their speech (`SpeechOnlyUpload`): the live lines of the track that are not echo, padded 0.5 s, joined when under 3 s apart, sent one after another with 0.6 s of silence between, and the cloud's word times put back on the meeting's clock (`UploadTimeMap`). A track the live pass heard nothing on goes whole (the live pass may have failed), one whose own speech covers 85 % or more goes whole, and one with only echo is not sent. On the 15 min test meeting this sends 839 s instead of 1802 s (−53 %, the cap counts what is sent) with no content words lost; the silence of a call and the other side's voice from the speakers are no longer paid for.

**AI fixes of the transcript (Pro).** `MeetingCorrectionProcessor` with `MeetingTranscriptCorrector`: the lines (no echo) go in batches of up to 80 lines / 7000 characters, three at a time, as `n|text` with the title and a glossary (dictionary + speaker names + the calendar participants, `MeetingTranscriptCorrector.glossary`); the relay (`transcript_correction`) answers the same numbered lines (`MeetingCorrectionPrompt` builds the data and parses the answer). A line is only swapped for its fixed version, never merged, split or dropped, and only when it keeps about the same number of words and characters, so a summary or an added sentence loses that line, not the transcript. Each fixed segment keeps `originalText`; "Przywróć transkrypt sprzed poprawek AI" (`Database.restoreOriginalTranscript`) puts it back. Word times are reused when the count matches, otherwise spread over the old span. `MeetingChat` is the shared non-streaming Captylo AI call of the fixes, the AI notes and the asks (relay only: an own-key route is refused as `noKey`; 402 is `quotaExceeded`, 401 / 403 `noKey`, other errors as `MeetingSummaryError`). There is no model to pick for meetings.

**Transcript actions.** Above the transcript in the details: where it comes from ("Transkrypt z Maca" / "z chmury", "poprawiony przez AI"), the last failure, and in Pro the "Popraw" menu (`MeetingTranscriptRuns`): "Popraw przez AI", "Transkrybuj ponownie w chmurze" (then the speaker labels again and, when "Poprawiaj transkrypt przez AI" is on, the AI fixes, like after a meeting), "Przywróć transkrypt sprzed poprawek AI". **Call detection.** `MeetingDetector` polls `CoreAudioProcesses.usingInput()` every 2 s off the main actor and maps the processes through `MeetingAppCatalog` (Zoom, Teams, Slack, FaceTime, Webex, Discord, Around, Tuple; Chrome, Safari/WebKit, Arc, Edge, Brave, Firefox; each entry has its main bundle ids plus helper prefixes). Nagrać notatki?" with "Nagraj", or "Wygląda na spotkanie „Budżet Q4” w X..." when a calendar event matches; "Nagraj" opens Spotkania and starts the recorder with that app and event (`recorder.linkedEvent`). **Search (Free).** `MeetingSearchIndex` (`Meetings/Search/`) is our own SQLite file next to the store, `AppPaths.searchIndex` = `Search.sqlite` (WAL, `PRAGMA user_version` = `MeetingSearchIndex.version`, 1), never SwiftData's private schema: an FTS5 table `entries(body, meeting UNINDEXED, segment UNINDEXED, kind UNINDEXED, start UNINDEXED, track UNINDEXED)` on the `trigram` tokenizer, a `keys` table (segment id, or `title:` / `notes:` + meeting id, to the FTS rowid, so an upsert or a delete never scans the FTS table) and `meta` (`meetings` and `builtAt` of the last full build). One row per segment that is not echo plus a title row and a notes row per meeting (empty ones too, so the counts stay stable). The body is folded with `MeetingSearch.fold` before it is stored (the tokenizer's own folding keeps "ł"); the original text is never stored, snippets come from the store, so the index never holds anything the store does not. `SearchQuery.terms` folds the query, splits on anything that is not a letter or digit (quotes and FTS5 operators never reach the index), keeps words of 3+ characters and stems them crudely (a Polish case ending "-cie", "-ach", "-ami", "-ie", "-om", "-ow", "-em" is dropped first, then at most 6 characters: "budżecie" finds "budżet", "ofercie" finds "ofertę", "cenach" finds "ceny"; otherwise a 4-character word drops a final vowel, other words up to 4 stay, 5-7 lose the last character, longer keep their first 6: "cena" finds "ceny", "oferta" finds "ofertę", "ofert", "ofertą"; "zarzad" finds "Zarząd"; "lodz" finds "Łódź"; never under 3 characters); `match(_:all:)` quotes each term and joins them with AND (the list; all terms in one entry) or OR (the library ask). Ranking is bm25 weighted x2 for the title and x1.5 for the notes. `meetingHits` ranks per meeting in SQL (a window function: every matching meeting up to the limit with its best N segment lines plus title / notes), so one meeting that repeats a word hundreds of times never pushes the others out. A class with its own serial queue rather than an actor: the SQLite handle lives only on that queue, and the `MeetingIndexing` writes are synchronous calls that only enqueue, in the order of the store saves.
- **Sync.** `Database` gets the index in `init(modelContainer:searchIndex:)` (nil in tests that do not need it) and calls it after every successful save, never throwing back into the store path (failures are logged): `appendSegment` and `updateSegments` upsert the segments (a segment marked echo is removed), `replaceSegments` (cloud transcript), `restoreOriginalTranscript` and `markInterruptedMeetings` (launch recovery, echo marks) reindex the whole meeting, `deleteMeeting` removes it, `createMeeting` / `updateMeeting` / `modifyMeeting` reindex the title and notes rows.
- **Launch.** `startServices()` runs `prepare(database:)` detached at utility priority: it opens the file and rebuilds when the file is new, of another version, fails `PRAGMA quick_check` (a corrupt file is deleted and recreated) or when the meeting count or the count of non-echo segments differs from the store's (a crash lost writes). `rebuild(from:)` empties the tables and refills them one meeting per transaction, newest first; each meeting is read and queued in one step on the `Database` actor, so a save during the rebuild is never lost. It logs "Search index rebuilt: N meetings, M rows in X ms" (counts only). Until the index is ready (`isReady`), or when it cannot be opened (`.unavailable`), the list search uses the old `Database.meetings(query:limit:)` `contains` path over the folded search text, and so do queries with no word of 3+ characters.
- **Isolation.** Only the real store gets the real file: an overridden store (design preview, test host) and the in-memory fallback store get an in-memory index (`AppStateOverrides.searchIndexURL`), so neither can empty the real index.
- **UI.** `MeetingsView` with a query that has terms calls `MeetingSearchResults.load` (`@concurrent`, off the main actor): `meetingHits` (AND, up to 200 meetings, 2 segment lines each), then `Database.meetings(ids:)` and `segments(ids:)`, ordered by best rank, newest on ties; under the search field "N spotkań". Each row shows up to two hit lines (`MeetingSearchHitsView`: `[12:34]`, the speaker, a snippet of about 80 characters cut on word boundaries with the matched words bold, built by `MeetingSearchSnippet` from the store's text), plus a "Notatki: ..." line when the notes matched and there is room. A click selects the meeting and opens "Transkrypt" scrolled to the line holding that segment (merged lines included) with a 1.5 s Tide highlight (`MeetingTranscriptJump`), or opens "Notatki" for a notes hit. Measured on a Debug build with 200 meetings x 600 segments (120k rows): 6-34 ms per query, 82 ms for a word in a third of the rows.

(`MeetingAskPrompt.notFound`, mirrored on the server) when the meeting has no answer. **MCP (Free, off by default).** A local, read-only [Model Context Protocol](https://modelcontextprotocol.io) server, so the user's own AI assistant (Claude Desktop, Cursor, ...) can list, read and search the meetings on this Mac. The assistant starts it as `Captylo --mcp` and keeps the process for its session; Captylo itself does not need to run.
- **Setting.** "Dostęp dla asystentów AI (MCP)" in Ustawienia > Spotkania (`MCPSettingsRow`, `AppSettings.meetingsMCP`, key `meetings.mcp`, default off). On, it shows "Skopiuj konfigurację", which copies `{"mcpServers": {"captylo": {"command": "<this binary>", "args": ["--mcp"]}}}` (pretty JSON, `MCPSettingsRow.configuration`) and a caption where to paste it. The server reads the setting from `UserDefaults.standard` (the app's domain) at every call: off, `tools/list` is empty and a known tool returns `isError` with "Włącz dostęp w Captylo: Ustawienia > Spotkania > Dostęp dla asystentów AI (MCP)."
- **Mode.** `CaptyloMain` (`@main`) handles `--mcp` before AppKit or SwiftUI start: no `NSApplication`, no `AppState`, no services, no menu bar item, no LaunchServices check-in (a checked-in process would take every later launch of Captylo from Finder, the Dock or the login item). `MCPStandardIO` claims stdout first: the real stdout is duplicated to a private descriptor that carries only JSON-RPC lines, and descriptor 1 goes to stderr, so nothing else can ever reach the protocol; SIGPIPE is ignored. The process exits when the client closes stdin.
- **Protocol.** `MCPServer`: newline-delimited JSON-RPC 2.0, requests handled one at a time, one line per response. `initialize` (the client's protocol version when it is 2025-06-18, 2025-03-26 or 2024-11-05, else 2025-06-18; `serverInfo` "captylo" with the bundle version; capability `tools`; short `instructions`), notifications ignored, `ping`, `tools/list`, `tools/call`; unknown method -32601, malformed JSON -32700, not a request or a batch -32600, unknown tool -32602, unreadable store -32603. Ids are echoed as sent (numbers stay numbers, `JSONValue`).
- **Tools** (`MCPTools`, JSON Schema inputs with `readOnlyHint` annotations, Markdown text results, descriptions in English for the assistant's model, result texts localized): `list_meetings {query?, since? (ISO date), limit? <= 50, default 20}` (one line per meeting: date and time, title, length, app, id; a query goes through the index, then `contains`), `get_meeting {id, transcript? = true}` (`MeetingExport.markdown(includeTranscript:)`, with participants and "Pytania"), `search_meetings {query, limit? <= 30 meetings, default 10}` (title, date, `[12:34] Speaker: ...snippet...` up to 2 lines per meeting, id; the index, or the store's `contains` when it is missing, building or the query is shorter than 3 characters). Bad arguments come back as `isError` results.
- **Read-only.** `MeetingLibraryReader` opens `AppPaths.store` with `Store.openReadOnlyContainer` (`allowsSave: false`, same schema): a store of another schema fails to open (the MCP process never migrates; the error asks to start Captylo once) and a missing store creates nothing. The index is opened with `SQLITE_OPEN_READONLY` (`MeetingSearchIndex(url:readOnly:)`) and answers only with the current version and a finished full build (`meta.meetings`, which a rebuild clears first and sets last). SQLite cannot open a WAL database read-only without its `-wal` file, so the reader creates an empty one when it is missing (`O_CREAT | O_EXCL`, an existing one is never touched); besides the `-shm` SQLite creates for any WAL reader, that is the only file the MCP process may create, and the databases themselves are never written. Both are reopened when the file or its `-wal` changed (modification date, size, inode), so a meeting saved by the running app shows up without restarting the assistant. SQLite WAL readers and the app's writer coexist safely. No AI calls and no network from this mode; the log gets only start, stop and failures (tool name and error type, never arguments or meeting text).
- **Privacy.** The server sends nothing anywhere: it answers the process that started it. Where the meeting text goes next is decided by the assistant the user connected.

**Clocks.** `MeetingTime.clock` renders `12:34` under an hour and `1:02:03` from one hour; the list, the details, the live bar and the capsule player (`AudioPlayerView.clock`, seconds truncated, not rounded) all use it, so a two-hour meeting never reads `125:00`.

**Pro.** Every Pro check goes through `ProAccess.isPro` / `allows(_:)`, which reads the Captylo account (`AccountStore.isPro`, see "Account and Pro"); debug builds also accept the switch "Tryb Pro (dev)" (`dev.pro`) and `CAPTYLO_DEV_PRO=1`; the design preview pins it. Free keeps recording, live local transcription, notes, list, search, export and the MCP server; "Zapytaj" (one meeting and all meetings) is `.meetingAsk`.

**Echo reduction (experimental).** "Redukcja echa (eksperymentalna)" in Ustawienia > Spotkania (`AppSettings.meetingsVoiceProcessing`, off by default) asks the meeting mic's input node for Apple's voice processing (`setVoiceProcessingEnabled(true)` with other-audio ducking at its minimum, `VoiceProcessingSetup`) before the tap is installed; the converter takes the changed native format and the feed still gets 16 kHz mono. An input that refuses it (some Bluetooth outputs, error -10875, at enable or at `engine.start()`) gets the plain engine and the recording always starts; `MeetingMicCapture.isVoiceProcessingActive` says what runs, and `Log.audio` prints "Meeting mic voice processing: on / off / unavailable (...)" once per start and again only when a rebuild (device change, wake) changes the outcome. Read at the meeting's start, so a change applies from the next meeting. `EchoFilter` stays as the second line. Open question for the field: whether VPIO's echo reference on macOS covers other apps' output (Zoom, Meet) or only what Captylo plays.

**Debug.** `--meeting-from-files <me-audio> <them-audio>` runs the pipeline on two files without the mic or the tap and reports the process peak memory; `--benchmark <audio>` runs the local model on one file with timings, peak memory and the word error rate (see the debug flags below). `PeakMemory` reads `task_info` `TASK_VM_INFO` (`phys_footprint` now, `ledger_phys_footprint_peak` since launch, through `task_self_trap()` because the global `mach_task_self_` does not pass Swift 6).

**Known limits.** Echo without headphones is removed from the transcript (`EchoFilter`, 3+ words that mostly repeat an overlapping "Rozmówcy" segment), not cancelled acoustically; short replies like "tak" are kept on purpose. A mic segment that only partly repeats the other side loses those runs of 4+ words heard on "Rozmówcy" within 1.5 s (word times), and keeps the user's own words: on the owner's meeting this removed 21 duplicated words without losing any (WER 31.4 % to 30.1 %). The HAL zero-buffer bug is handled by rebuilding the tap, which can leave a short gap. Browser meetings are detected only with the Accessibility grant and a call service in a window or tab title; Arc exposes no readable tab strip, so an Arc call ends only when the mic is released or the app quits. Slack huddles and FaceTime have no reliable title, so their mic use alone is the signal, and FaceTime audio may run in a system daemon the catalog does not see. The calendar only helps a recording that starts within an event's window; an event without a call link is matched but never reminded about, and the calendar-based end needs a detected call app. Voice processing is a switch, not a promise: outputs that refuse it fall back silently. Diarization needs macOS 15+.

## Account and Pro

Pro is a subscription on a Captylo account; the server side (`api.captylo.com`) is a private service, not part of this repo (see "Open core" at the top).

- **Module.** `Captylo/Account/`: `AccountClient` (pure request builders and parsers plus one `send` over `HTTP.accountSession`; every failure is an `AccountError` with a Polish text), `AccountInfo` / `AccountPlan` / `AccountUsage` / `BillingPlan` (values of `/v1/me`), `AccountStore` (`@MainActor @Observable`, owned by `AppState`), `AccountUsageFormat` (the usage bars' texts), `CloudRouter` + `CloudCredential` + `AIRoute`, `DeepLinkKind`. Views in `Captylo/UI/Main/Account/`: "Konto Captylo", the first panel in Ustawienia (e-mail, then the 6-digit code; then the plan, usage bars, "Przejdź na Pro" / "Zarządzaj subskrypcją", "Wyloguj"; a subscription that is `past_due` or `unpaid` shows "Płatność nie przeszła. Zaktualizuj kartę." with only "Zarządzaj subskrypcją", never the buy buttons, and the server's 409 `payment_pending` is `AccountError.paymentPending`), and `ProStatusCard` on Modele. `MainRouter.openAccount` opens that panel.
- **Source of Pro.** `ProAccess.isPro` = `AccountStore.isPro`: a signed-in account whose plan is Pro and was confirmed by the server within 7 days (`AccountStore.cacheMaxAge`). Debug builds also accept "Tryb Pro (dev)" and `CAPTYLO_DEV_PRO=1`; release builds ignore both.
- **Session and cache.** The session token lives in the login Keychain (`KeyStore.Account.captyloAccount` = `captylo-account`, read off the main actor with a 10 s timeout); the last `/v1/me` is cached as JSON in `account.cache` with `account.refreshedAt`, so the plan is known at launch before the network answers. `start()` (from `startServices()` only) refreshes at launch and every 6 hours; the app coming to the front within 30 minutes of opening a Checkout or Portal page refreshes too (`appDidBecomeActive()`, the user may close the tab without the deep link), and the "Konto Captylo" panel refreshes a plan older than 5 minutes when it appears (`refreshIfStale()`). Offline or a server error keeps the cache (Pro for up to 7 days, then Free with a hint until a refresh succeeds); a 401 signs out at once and clears the cache; a token the Keychain cannot read right now (denied ACL prompt, locked keychain) keeps the account and retries, only a token that is really gone signs out. "Wyloguj" forgets the token and the cache first, then revokes the session on the server (best effort).
- **Routing (`CloudRouter`).** The meeting AI asks `relayAIRoute` (the Pro session only, never an own key). The dictation AI passes `preferRelay` = `AppSettings.aiCaptylo` (on by default; "Captylo AI", the first row of the model list in Pro, turns it on, any other model turns it off): with it a Pro session goes to the relay even when an own key is saved, and without Pro the own key still works. Cloud transcription does the same with `sttCredential(preferRelay:)` = `AppSettings.sttCaptylo` ("Chmura Captylo" vs "Własny klucz" in Modele > Zaawansowane, on by default; removing the own key in Pro turns it back on). In Modele, "Podstawowe" shows what runs each service (`CloudSource`, the same rule) with "Zmień" / "Dodaj klucz" opening "Zaawansowane", where the key fields, the source picker and the model list live. Every other cloud request asks the router: the user's own key -> the vendor directly, the chosen model honoured; otherwise the Pro session token -> the relay at the account base URL (the server picks the AI model; the STT request carries `Authorization: Bearer` and `X-Captylo-Audio-Seconds` instead of `xi-api-key`); otherwise no route (local only, or the "no key" text, which mentions Pro). Resolved per request: adding or removing a key, signing in or out applies to the next request without a restart. On the dictation path it is one cached Keychain read plus the in-memory Pro check within the same deadline. The relay's 402 is `quotaExceeded`: the take falls back to the local model and the toast says the month's limit is reached; 401 / 403 mean no access.
- **Deep links.** `captylo://pro/done` (the site's page after Checkout) and `captylo://account/refresh` (after the Portal) go from `AppDelegate.application(_:open:)` to `AppState.handleDeepLink`, which refreshes the account now, after 3 s and after 10 s (the webhook may lag the redirect) and opens "Konto Captylo"; other `captylo://` links are ignored and logged without the URL.
- **Relay URL.** `CAPTYLO_API_BASE=<http(s) URL>` points the account client and the relay at another server (a local `npm run dev`); anything else falls back to `https://api.captylo.com/v1`.
- **Isolation.** The design preview and the test host pin the account (`AppStateOverrides.pinnedAccount`, `CAPTYLO_PREVIEW_ACCOUNT=signedout|code|free|pro` in the preview) on an in-memory key store: they never read the Keychain, never refresh and never hand out a relay token, so neither reaches the network. `--check` prints the account state (signed in, plan, cache) without calling the server.

## Windows

The look of every window follows the Dusk Glass design language in the Deep Tide palette: [docs/design/dusk-glass.md](design/dusk-glass.md) (every window is an opaque animated background, by default the Metal "Grainient" gradient, with clear frosted glass panels on it; Manrope + Inter bundled in `Resources/Fonts`; component catalog, widget states, screen-by-screen guidance, the design preview harness).

- Recorder widget: borderless `.nonactivatingPanel`, `canBecomeKey = false`, level `.floating`, all Spaces, bottom center of the screen under the mouse, fixed transparent canvas sized for the expanded state (`RecorderMetrics.canvas`, 448 x 544 pt) with content bottom-anchored; SwiftUI animates inside it. No window shadow (the widget draws its own glows). Clicks on transparent pixels fall through to the app below.
- Widget hover: an `NSTrackingArea` with `.activeAlways` (the panel is never key and the app is usually inactive) plus a 150 ms pointer check while the widget is up; the pointer resting 0.28 s on the widget expands it, leaving it for 0.45 s collapses it, an open row menu keeps it open. The expanded rows go through `RecorderWidgetControls` (`RecorderAppControls`: `AppSettings`, `AudioDevices`, `RecorderCoordinator.togglePause`); a microphone picked mid-take applies from the next take. The "Tryb AI" row, the menu bar submenu of the same name and a click on a mode row in Modele all set `aiEnabled` / `aiActiveModeID` through `RecorderAIModeOptions.select`: "Bez AI" only turns the master switch off, a mode turns it on, so the three surfaces never disagree. The widget menu and the menu bar submenu end with "Edytuj tryby...", which opens the main window on Modele (`RecorderWidgetControls.openModes`, wired in `AppState`). The controller reads the mode when the take stops, so a pick made while recording applies to that take; `RecorderModel.enhancingModeName` captures the running mode when the phase turns `.enhancing` for the status line "Poprawiam z AI · <tryb>". Row menus are plain `NSMenu`s popped from buttons, because a SwiftUI `Menu` in a non-key panel can swallow the first click.
- Toasts: one reusable non-activating panel above the widget (small Dusk Glass capsules).
- Main window: `Window("main")` with sidebar (Pulpit, Spotkania, Historia, Transkrypcja pliku, Słownik, Modele, Ustawienia), ~920 x 640 min. The shell is an `HStack` (`MainSidebar` attached to the left edge + content column), not `NavigationSplitView`, whose system sidebar would paint its own material; Cmd+1...7 and the arrow keys (sidebar focused) switch sections through the `MainRouter`. Dock icon policy switches to `.accessory` when "Ukryj ikonę w Docku" is on and no main window is open.
- Support card (Free plan monetization): a small raised card at the bottom of `MainSidebar`, visible on every section, never in the widget or onboarding. `SupportPromo` picks one message a day (`dayNumber` modulo the options): "Captylo Pro" (opens "Konto Captylo" in Ustawienia) and "Postaw kawę twórcy" (opens https://captylo.com/kawa/, a page on our site that holds the Stripe Payment Link, so the link changes without an app release). "x" hides it for 14 days (`AppSettings.supportCardHiddenUntil`). A paid sponsor joins the rotation by setting `SponsorAd.current` in a release; it is compiled in, never fetched, so no network call is made. The card still shows for Pro accounts; hiding it for them is a follow-up.
- Menu bar extra: start/stop dictation, "Nagraj spotkanie" / "Zakończ spotkanie" (⌃⌥⌘M), copy last transcript, microphone and "Tryb AI" submenus, open app, settings, quit. Icon swaps to the `MenuBarIconRecording` template asset while a take or a meeting records (a status item flattens its label, so no overlay dot).

## Debug CLI flags (kept in Release, documented for support)

Run `Captylo.app/Contents/MacOS/Captylo <flag>`; the app runs headless, prints JSON to stdout and exits:

- `--transcribe <audio file> [--ai] [--language pl] [--engine local|cloud]` - full pipeline without the mic (decode → engine → spelling → text processing → optional AI). `--engine` overrides the setting (`local`, also accepted as `whisper` or `parakeet`, never reads the Keychain without `--ai`); the local model is loaded before the pass, so `transcriptionMs` is the pass alone. Output: `{"text","rawText","spelled","enhancedText","modelName","transcriptionMs","enhancementMs"}`; nothing is learned from a debug run.
- `--meeting-from-files <me-audio> <them-audio>` - the meeting pipeline without the mic or the system audio tap (no TCC): both files are decoded to 16 kHz mono and fed from meeting time 0 in 4096-sample chunks, alternately, into a real `MeetingTranscriber` (the app's Whisper engine, Silero VAD, echo marks at the end) that saves into an in-memory store. Uses the transcription language setting; the model must be downloaded. With Pro on (`CAPTYLO_DEV_PRO=1` or the dev switch) and macOS 15+ it then labels the speakers of the `them` file like after a real meeting (the offline diarizer downloads its models on first use). Output: `{"ok": true, "segments": [{"track": "me", "start": 1.2, "end": 3.4, "text": "...", "echo": false, "speaker": null}], "transcribed", "language", "speakerTurns", "voices", "ms", "peakMemoryMB"}` (segments as stored, in transcript order; `transcribed` differs from their count only when a save failed; `speakerTurns` and `voices` are null when no diarization ran, and `speaker` stays null with fewer than two voices; `peakMemoryMB` is the process peak footprint, the number to watch in a 2 h soak), or `{"ok": false, "error"}`.
- `--benchmark <audio file> [--reference <txt file>] [--language pl]` - the owner's accuracy and speed check: transcribes the whole file with the app's local engine (the installed Whisper model; long files are cut at pauses into 30 s windows). `--language` works like `--transcribe` (default: the transcription language setting). Output: `{"ok": true, "file", "durationSeconds", "language", "reference": <bool>, "model", "text", "loadMs", "ms", "rtf", "peakMemoryMB", "memoryDeltaMB", "wer": {"percent", "substitutions", "deletions", "insertions", "words"} | null}`. `wer` (`WordErrorRate`, word Levenshtein on folded, punctuation-free tokens) needs `--reference`; `loadMs` includes the Neural Engine compile on the first load of a model; `peakMemoryMB` is sampled every 100 ms while the model loads and runs. A language code outside the picker list fails instead of running as auto.
- `--watch-paste <text>` - hidden self-learning check: pastes the text into the focused field like a dictation, watches it like after a dictation and prints the learning memory when the watch ends. Run it with `CAPTYLO_DATA_DIR=<scratch folder>` so the lessons land there.
- `--show-widget <recording|transcribing|enhancing>` - shows the widget with fake levels and sample live text and stays up until killed (for screenshots with `screencapture -x`).
- `--check` - prints permission states, model status, selected device, hotkey, the data paths, the active AI mode, the history row count and the account state from the cache (`signedIn`, `plan`, `cached`; never the address or the token, no network). It reads the Keychain, so an ad-hoc Debug build can block on an ACL prompt.

- `--rebuild-search-index` - empties the meeting search index (`Search.sqlite` next to the store) and fills it again from the store this run opened, like a launch that found it out of step. Refuses the in-memory fallback store (it would empty the index). Output: `{"ok": true, "file", "meetings", "rows", "ms"}` or `{"ok": false, "error"}`. Use `CAPTYLO_DATA_DIR` with a copy of the store for checks; it migrates that store like a normal launch.
- `--mcp` - the read-only MCP server (see "MCP" under Spotkania) on stdin/stdout for an AI assistant; not a support tool. Handled by `CaptyloMain` before AppKit starts, runs until the client closes stdin, prints nothing but JSON-RPC lines on stdout. Reads the store and the index at `AppPaths` read-only, so `CAPTYLO_DATA_DIR=<copy>` for manual checks; `-meetings.mcp YES` on the command line turns the setting on for that run only (argument domain), without touching the real defaults.

`CAPTYLO_DATA_DIR=<folder>` points `AppPaths` (store, search index, dictionary, recordings, meetings) at another folder for support and for migration checks on a copy of the store. Settings still come from the real defaults domain.
- `--reset-onboarding` - clears onboarding progress.
- `--ax-probe [--show-text]` - hidden self-learning spike tool: once a second prints a one-line JSON when the focused text field changes (bundle id, role, subrole, length, readable, selection). Sets `AXManualAccessibility` once per frontmost app so Electron apps expose their fields. The field text (last 80 characters) is printed only with `--show-text`. Runs until killed; needs the Accessibility grant. Findings go to [docs/reference/ax-coverage.md](reference/ax-coverage.md).
- `--open-section <pulpit|spotkania|historia|plik|slownik|modele|ustawienia>` - hidden screenshot helper: a normal GUI launch (services, tap, menu bar) that skips the onboarding and opens the main window on that section.
- `--design-preview <target>` - hidden design helper: one screen (widget state, onboarding step, main section or `glass-gallery`) on fake services built through `AppStateOverrides` (in-memory store with sample history and three sample meetings, Pro pinned on unless `CAPTYLO_PREVIEW_FREE=1`, defaults suite `com.captylo.app.design-preview` wiped at start, temp dictionary, seeded key store, pinned local model "ready", a pinned "ready" voice detector, Accessibility, and a `FixedCalendarSource` that is empty unless `CAPTYLO_PREVIEW_CALENDAR=1` seeds three invented events; EventKit is never created; an in-memory search index; "Zapytaj" never calls the network). Spotkania also reads `CAPTYLO_PREVIEW_TAB=notes|transcript|ai|ask`, `CAPTYLO_PREVIEW_QUERY=<q>` (the search field opens with `q` typed, e.g. `oferta`), `CAPTYLO_PREVIEW_HIT=1` (with a query: the first hit line clicked) and `CAPTYLO_PREVIEW_ASK_ALL=1` (the "Zapytaj wszystkie spotkania" panel with a seeded answer); the full list is in `scripts/snap.sh`. No services, no hotkey tap, no menu bar item, never activates the app. Prints `WINDOW_FRAME=x,y,w,h` and `WINDOW_ID=<n>` when the window is up (optional `CAPTYLO_PREVIEW_BACKDROP=white|dark|<image>` puts a backdrop window behind it) and runs until killed; unknown target = JSON error, exit 64. Driven by `scripts/snap.sh <target> <out.png>` (see dusk-glass.md).

When the app is the unit-test host (`XCTestConfigurationFilePath` set) it skips `startServices()` and the onboarding, so `make test` never installs a second hotkey tap. It builds `AppState` on `AppStateOverrides.testHost()` (in-memory store and search index, temp dictionary, wiped `com.captylo.app.test-host` defaults suite), so a schema change can never migrate the user's store while a real Captylo is running.

Schema changes stay additive and optional (or defaulted), so SwiftData migrates the store in place without a `VersionedSchema`; `DatabaseMigrationTests` keeps a frozen copy of the previous schema and checks both the upgrade and a rollback to it.

## Build and install

`make gen` (XcodeGen), `make build` (Debug, `.local-build/`), `make test`, `make release` (Release, re-signed inside-out with Captylo Dev or ad-hoc through `scripts/sign-app.sh`, build number 1 so Sparkle stays off, copied to `~/Downloads/Captylo.app`), `make install` (also copies to `/Applications`), `make check` (Debug binary `--check`), `make reset-tcc` (resets the `com.captylo.app` grants). The first load of the local model compiles it for the Neural Engine (2-3 min, once per model, cached by Core ML); later loads ~0.3 s.

Public releases ([release.md](release.md)): `make dist VERSION=x.y.z` builds Release with `CFBundleVersion` = 100 + `git rev-list --count HEAD` (`BUILD_BASE`, see [release.md](release.md)), signs with Developer ID, notarizes, staples and packages `dist/<version>/Captylo-<version>.dmg` (hdiutil, UDZO, an Applications shortcut), then writes the appcast item (`site/updates/appcast.xml`) and the release notes page (`site/updates/notes/<version>.html`) through `scripts/appcast.py`; the website (its own repository since 2026-10-04) reads the version from the appcast. `make publish VERSION=x.y.z` (`scripts/publish-release.sh`, `--check` for the local checks only) uploads the DMG to the downloads folder on the server (`PUBLISH_DOWNLOADS` in the git-ignored `deploy/local.env`), points `Captylo.dmg` at it, syncs `site/updates/` into the server's `updates/` folder and creates the GitHub release `v<version>` with the DMG. Caddy serves `captylo.com/download/*.dmg` from that folder and `/updates/*` from the synced folder, never cached (`deploy/Caddyfile.captylo.snippet`); every other page, `/download/` included, is the website's. `dist/` is git-ignored.
