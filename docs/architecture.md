# Architecture

Captylo is a single macOS app target plus a unit-test target. Everything is built from `project.yml` with XcodeGen. The old app it replaces (a VoiceInk fork) is only a reference: its behaviour was mapped into `docs/reference/port-notes/`, and the consolidated `REWRITE-BRIEF.md` there lists 87 numbered gotchas with the module they apply to. This file records the decisions that override that brief.

## Decisions (override the brief where they differ)

| Topic | Decision |
|---|---|
| Deployment target | macOS 14.4, arm64. Liquid Glass behind `#available(macOS 26, *)`, `.ultraThinMaterial` + 0.5 pt white stroke fallback. No `Synchronization` module (needs 15): use `OSAllocatedUnfairLock` for shared mutable state on audio paths. |
| Speech engines | Local Parakeet TDT 0.6b v3 via FluidAudio 0.17.4 (default) and ElevenLabs `scribe_v2` (cloud). Nothing else. Cloud failure falls back to Parakeet when the model is installed. Live preview always uses Parakeet. |
| AI cleanup | OpenRouter only (`POST https://openrouter.ai/api/v1/chat/completions`, `Authorization: Bearer`, app attribution headers `X-Title: Captylo` and `HTTP-Referer: https://captylo.com`). Model list from `GET https://openrouter.ai/api/v1/models` (public, cache 24 h, filter text in/out). Default model `openai/gpt-4.1-mini`; quick picks `openai/gpt-oss-120b`, `google/gemini-2.5-flash-lite`, `anthropic/claude-haiku-4.5`, `mistralai/mistral-small-3.2-24b-instruct`. Body: `temperature 0`, `max_tokens` rule from the brief, `reasoning: {"enabled": false}`, `provider: {"sort": "latency"}`. Hard deadline 3.0 s, no retries, raw text on failure. Prewarm and key check: `GET https://openrouter.ai/api/v1/auth/key`. |
| AI modes ("Tryby AI") | The prompt comes from the active `AIMode` (`AppSettings.aiModes` / `aiActiveModeID`, JSON in `ai.modes`), `ai.enabled` stays the master switch ("Bez AI"). Built-ins (`BuiltInAIModes`, fixed ids): Czyszczenie (the cleanup template, 3 s), Po angielsku (6 s), Uporządkuj myśli (8 s), E-mail (6 s), Lista zadań (6 s). Kind `.cleanup`: skip at 3 words or fewer, reject empty / `finish_reason length` / length ratio outside 0.4...2.5, cap `min(2048, est * 2 + 64)`. Kind `.rewrite`: any non-empty text, reject only empty or cut off, cap `min(4096, est * 3 + 256)`; gpt-oss `+ 512` for both. Deadline per mode, clamped to 1...20 s, so `HTTP.llmSession` times out above 20 s and the Swift race is the real limit. A custom `ai.prompt` from before modes becomes "Mój prompt" (active) until the list is first saved. Every AI dictation stores `enhancementMode` and, when there is no AI text, a short Polish `enhancementNote` (AI off: both nil). "Przetwórz przez AI" (`HistoryActions.reprocessWithAI`) and "Testuj tryb" (`ModeTester`) use `AppState.utilityEnhancer` (file session, 15 s) and never add a `UsageStat`. |
| Audio capture | `AVAudioEngine` input tap, device chosen with `inputNode.auAudioUnit.setDeviceID(_:)` before start. One persistent `AVAudioConverter` to 16 kHz mono Float32. WAV written with `AVAudioFile` (Int16, 16 kHz, mono). Stop = remove tap, stop engine, close file, then read. No raw AUHAL, no ring buffer. |
| Hotkeys | `CGEventTap` on its own thread, hybrid mode only (tap < 0.5 s latches, hold >= 0.5 s is push-to-talk), default Right Option, presets Fn and Right Command, custom combos via recorder. Esc twice cancels while the widget is visible. Accidental-start guard for Right Option + letter. |
| Live transcript card | Lives in the expanded widget (mockups 03/04), which opens while the pointer rests on the widget. The compact state is exactly mockup 01 (orb, free-floating waveform, timer) and shows no text, so a take never grows a card over the app being dictated into. Both states are bottom-anchored near the screen edge. |
| Output | Pasteboard + synthetic Cmd+V from a `.privateState` event source, stamped with `eventSourceUserData = 0x56544332` so our own tap ignores it. Clipboard restored after 2 s if `changeCount` is unchanged. Paste failure = text stays on the clipboard + toast. |
| Identity | Product "Captylo", bundle id `com.captylo.app` (tests `com.captylo.app.tests`), `Captylo.app` with executable `Captylo`, Keychain service and `os.Logger` subsystem `com.captylo.app`, URL scheme `captylo`. Website https://captylo.com is the only public address. |
| Data | SwiftData at `~/Library/Application Support/Captylo/Captylo.store` (configuration `Captylo`, `cloudKitDatabase: .none`), `dictionary.json` next to it, `Recordings/<id>.wav`. `UsageStat` is append-only and drives the dashboard; deleting history never changes totals. Schema is import-friendly for the old store (phase 2, not built now). |
| UI language | Polish source strings, English translations in `Captylo/Resources/Localizable.xcstrings` (Info.plist strings in `InfoPlist.xcstrings`). Numbers and dates follow the UI language through `AppLocale`. Mockup strings are used verbatim. |
| Signing | Xcode builds ad-hoc (`CODE_SIGN_IDENTITY=-`), hardened runtime on, sandbox off. `make release` then re-signs `~/Downloads/Captylo.app` with the local self-signed identity "Captylo Dev" (`make sign`, created once by `scripts/setup-signing.sh` in its own keychain `captylo-dev.keychain-db`), so the designated requirement is certificate-based and Microphone/Accessibility grants survive rebuilds. Without that identity builds stay ad-hoc and grants are per build hash (`make reset-tcc`). Distribution to other Macs needs a Developer ID + notarization. |
| Self-learning | Local only, no server (Honcho and similar were rejected: privacy and the Free plan). Switch `learning.enabled` ("Ucz się z moich poprawek", default on). Sources: words spelled out loud (`SpellingDetector`, before `TextProcessor`; a take that is only a spelling, "Pisane J-E-V", is not pasted and corrects the closest word of the previous take) and edits of pasted text read back through Accessibility (`EditWatcher`: only the pasted field, polled twice a second; when our text leaves the field (a chat message sent, the box cleared) the watch ends with the last text that still held it; ends when the field loses focus (its own `AXFocused` first) or the app changes, on the next take, 90 s idle or 10 min; never secure fields, password managers or terminals; `start()` calls `prepare()`, which sets `AXManualAccessibility` on the frontmost app and, for Chrome-family browsers, `AXEnhancedUserInterface`, so the tree is built by paste time; every AX call runs off the main actor behind a deadline (`EditWatcher.offMain`: 150 ms for the snapshot before Cmd+V, else no watch; 2 s while watching) on top of a 0.5 s AX messaging timeout; browser results in docs/reference/ax-coverage.md). `CorrectionLearner` (pure) keeps 1...3-word term fixes, sends bigger edits to style samples and drops rewrites (< 50 % words kept) and text typed after the paste. A pair is learned at the first sighting (the owner's workflow: select the word, retype it, done; `SelfLearning.threshold` = 1, the Cofnij toast is the safety net): the correct form joins the vocabulary, and a replacement rule is added only when the misheard side is not a real word (`NSSpellChecker` pl + en), otherwise it is an AI hint. Every lesson shows "Zapamiętałem: a → B [Cofnij]"; undo removes what it added and blocks the pair; correcting a learned form back drops the rule, twice forgets it. Style: every 8 samples the utility enhancer (15 s, only with AI on) distills a profile of at most 700 characters, editable in Słownik; the prompt gets the hints, the profile and the target app name. Memory in `learning.json` next to the dictionary (so test host and design preview use temp copies). Settings also hold `learning.notifications` (the toasts) and `learning.excludedApps` (bundle ids picked as .app in Ustawienia > Nauka, on top of the built-in list). Every watched paste, edited or not, adds to daily `editStats`; Pulpit shows "Poprawki/100 słów" over 14 days once there are 50 watched words. The learned vocabulary does not reach Parakeet itself: FluidAudio's CTC boosting uses an English CTC encoder that replaces real Polish words (docs/reference/ctc-boosting-spike.md), so Parakeet still ignores vocabulary. |
| Dependencies | FluidAudio only. Apple frameworks otherwise. |

Ownership rule: a module talks to another only through the protocols in `Dictation/DictationTypes.swift` and the concrete types listed in the brief section 4. `AppState` builds every service once in `init` (safe for the headless debug commands) and injects them; `startServices()` adds the launch behaviour of a GUI run (tap install on the Accessibility grant, audio and Parakeet prewarm, the meeting voice detector prewarm, retention, the calendar refresh loop and reminders, call detection, settings observers). No singletons except `Log`. Shell hooks the controller needs (open Modele, open a Settings pane, bump stats) are closures in `DictationEnvironment`, so `Dictation/` never imports the window layer. `AppState` also owns the `FileTranscriptionQueue`: Finder "Otwórz za pomocą" files are stashed in `pendingOpenURLs` until `startServices()` has created the data directories, then fed to the queue and the main window opens on Transkrypcja pliku; the drop zone feeds the same queue.

## Dictation flow

1. `HotkeyTap` (background thread) → `HotkeyController` (MainActor) decides tap vs hold → `DictationController.start()`.
2. `start()`: mic permission check, device resolve, `AudioCapture.start` (samples into `SampleBuffer`, WAV to disk), after 150 ms play the start sound, show the widget, mute system output; `LivePreview` re-transcribes the last 15 s every second while recording.
3. `stop()`: stop capture, `TranscriptionRouter` (Parakeet full pass or ElevenLabs upload with Parakeet fallback), `SpellingDetector` (words spelled out loud), `TextProcessor` (tags, fillers, whitespace, paragraphs, replacements), optional `Enhancer` (OpenRouter, 3 s deadline, prompt with the learned hints and style), stop sound, hide widget, `EditWatcher.willPaste`, `TextOutput.deliver` (pasteboard + Cmd+V + restore), `EditWatcher.didPaste`, then `Database.save`, bump `statsVersion` and learn the spelled words. `start()` of the next take flushes the watcher first.
4. `cancel()` (Esc twice, or accidental-start guard) aborts capture, deletes the WAV, hides the widget, saves nothing.

Timing budget on Apple Silicon: key-up to paste <= 400 ms local; with AI cleanup p50 ~1 s, never more than deadline + 0.3 s.

## Spotkania (notetaker)

Records a call on the Mac without a bot: the mic as "Ja" and everything the Mac plays as "Rozmówcy", two separate tracks, transcribed live and locally with Parakeet. Separate from the dictation path: the dictation hotkey keeps working during a meeting and both transcripts land.

**Layout.** Logic in `Captylo/Meetings/` (recorder, transcriber, feeds, echo filter, export, retention, launch resume, `ProAccess`), with `Audio/` (sources, track files, watchdog, Core Audio process list, voice processing), `Speakers/` (diarization), `AI/` (templates and notes), `Detection/` (call detection) and `Calendar/` (the user's calendar, matching, reminders). Views in `Captylo/UI/Meetings/` (sidebar section "Spotkania": the "Nadchodzące" strip, list, live view, details with transcript, "Moje notatki" and "Notatki AI", settings panel). Storage in `Data/MeetingModels.swift` (`Meeting`, `MeetingSegment`) and `Data/Database+Meetings.swift`. One type per file; tests in `CaptyloTests/Meeting*Tests.swift` with fakes in `MeetingFakes.swift`.

**Data flow.**

1. `MeetingRecorder` (`@MainActor @Observable`, one meeting at a time) refuses to start without the speech model on disk (`MeetingEnvironment.speechModelReady`: every pass would fail and the meeting would end with no transcript; Spotkania shows "Brakuje modelu mowy" with "Otwórz Modele"), then creates the `Meeting` row (`start(title:appName:event:)`: an explicit event, or with no title the event `MeetingEnvironment.currentEvent()` matches now, gives the title, `calendarEventID`, `participants` and the app name from its call link; a default "Spotkanie w Zoom, ..." title only without an event), suppresses `SystemMute` for the whole meeting (a dictation take never mutes the call) and starts the sources on its own serial queue: `MeetingMicCapture` (default input on its own `AVAudioEngine`, rebuilt on device changes, holes filled with silence; `MeetingEnvironment.makeMic` runs on the main actor at start, so it reads "Redukcja echa" then) first, then `SystemAudioTap` (global Core Audio process tap excluding Captylo, private aggregate device, converted to 16 kHz mono Float32). "Nagraj spotkanie" (menu bar, Spotkania, the detector) always opens Spotkania first: a meeting never records without its live bar and the menu bar state.
2. Each source feeds a `MeetingTrackFeed`, which keeps the track on the meeting clock (pads the start and rebuild holes) and hands every buffer, under one lock, to a `TrackFileWriter` (`me.caf` / `them.caf`, 16 kHz mono Int16, appended as recorded) and to the `MeetingTranscriber` actor.
3. `MeetingTranscriber`: per track, 4096-sample chunks -> Silero VAD (shared `SpeechDetectorCache`) -> utterances of at most 14 s -> timed Parakeet pass (word times) -> `MeetingSegment` saved right away. Partials (the grey line) about once per second of speech. Memory per track is one open utterance, never the whole meeting. When the VAD cannot load or a pass throws (no or a broken model), the transcriber sends `MeetingLiveUpdate.problem` and the live bar warns that no transcript is being made until it works again. The VAD (about 1 MB, downloaded once by FluidAudio) is fetched ahead of the first meeting: `SpeechDetectorStatus` (`AppState.speechDetectorStatus`, states missing / loading / ready / failed) calls `SpeechDetectorCache.prewarm()` after a successful Parakeet download (`ParakeetModelStore.onDownloaded`) and in `startServices()` after the Parakeet prewarm when the model is installed; Modele and the onboarding model step show it under the model status as `SpeechDetectorStatusLine` ("Wykrywanie mowy do spotkań: gotowe" / "pobieram..." / "nie pobrano (...)", nothing while missing). A failure is only logged and shown there; a meeting started meanwhile loads the detector itself.
4. `stop()` closes the sources and files, `finish()` marks echo between the tracks (`EchoFilter`), the row gets its length and goes to "processing", and the recorder is idle again (a back-to-back call can be recorded at once; the detector asks about a call that started while the last meeting finished once the recorder is idle). The post-processors (`MeetingPostProcessing`) then run in the background, one meeting at a time in stop order: `MeetingCloudTranscription` (Pro, "Dokładniejszy transkrypt z chmury"), `SpeakerLabelProcessor` (Pro, macOS 15+), `MeetingCorrectionProcessor` (Pro, "Poprawiaj transkrypt przez AI"), `MeetingNotesProcessor` (AI notes, Pro), `MeetingRetention` (last, it may delete the audio the first ones read). Then "completed" and `processedCount` bumps, so Spotkania reloads the labels and the notes. Meanwhile the list says "Przetwarzam" and "Notatki AI" says "Piszę notatki...".
5. Crash or quit: segments saved so far stay, the CAF files stay readable (`abortForTermination` closes them on a normal quit); `recoverInterruptedMeetings()` marks the row "Przerwane" at the next launch, marks its echo (the stop never did) and gives it a length (the longer of the track files and the last segment). A quit while the post-processors still run leaves the row "processing": the transcript, echo marks and length were saved by the stop, only the extras were cut. `Database.markInterruptedMeetings` returns a `MeetingRecovery` (`interrupted` plus `resumed`, the "processing" rows marked "completed" in stop order) and `resumeProcessing(ids:)` queues `MeetingEnvironment.resumeProcessors` on the same serial chain as a stop, with `reopen`: the row reads "processing" again, then "completed" and `processedCount` bumps. The resume list holds only the AI steps, each behind a `MeetingResumeStep` that skips work already on the row (`MeetingCorrectionProcessor` when `transcriptAIModel` is nil, `MeetingNotesProcessor` when `summary` is nil; their own Pro and setting gates still apply), then `MeetingRetention`; never the cloud pass and never the diarizer (a crash there must not repeat at every launch). A crash during the resume leaves finished steps done, so the next launch runs only what is still missing. "Napisz notatki" and "Popraw" keep working on an interrupted row.

**System audio checks.** A denied grant and the long-session HAL zero-buffer bug both deliver exact zeros with `noErr` everywhere. `SilenceWatchdog` sees zeros while another process plays output (`CoreAudioProcesses.anyOtherProcessPlaying()`); `SystemTrackWatch` decides. Before any audio: the tap is rebuilt after 8 s of zeros, then 12 s, 20 s, 40 s and every 120 s (a tap made before the first grant can stay on zeros after "Allow"), and only after 30 s does the live bar say "Na razie nie słyszę rozmówców..." with the way to System Settings (a call often starts in silence). After audio: quiet tap rebuilds (30 s, 30 s, 60 s, then every 120 s of zeros) and a gap ("przerwa w nagraniu") when a rebuild brought the audio back. Ustawienia > Spotkania > "Sprawdź" runs the tap for 2 s (`SystemAudioCheck`). The headphones hint shows while the default output is the built-in speakers.

**Permissions.** Microphone (existing) plus "System Audio Recording Only" (`NSAudioCaptureUsageDescription` in `project.yml`, English in `InfoPlist.xcstrings`; the prompt appears at the first `AudioDeviceStart` of the tap, there is no public API to ask or query it; deep link `Privacy_AudioCapture`). No Screen Recording, no ScreenCaptureKit. Meeting detection reads browser window and tab titles through the Accessibility grant the hotkey already needs. Calendar (optional, Free): full access to events (`NSCalendarsFullAccessUsageDescription` in `project.yml` + `InfoPlist.xcstrings`, asked with `requestFullAccessToEvents()` the first time "Kalendarz" is switched on; deep link `Privacy_Calendars`). On macOS 14 "Add only" in another app's prompt leaves Captylo `writeOnly`, which is explained like a denial, never treated as granted.

**Diarization.** "Mówca 1/2/3" on the "Rozmówcy" track only with `ProAccess.allows(.speakerLabels)` and macOS 15+: FluidAudio's `OfflineDiarizerManager` crashes on macOS 14 (FluidAudio #878, an Apple BNNS bug fixed in 15). It reads the closed `them.caf`; one remote voice or any failure keeps "Rozmówcy".

**AI notes (Pro).** `MeetingSummarizer` sends one non-streaming request over the whole transcript (a 1 h meeting is about 20-25k tokens) through `OpenRouterClient` on `HTTP.meetingLLMSession` (150 s idle, 180 s total), with the user's AI model and key. The prompt carries the title and, when the meeting came from a calendar event, a "Uczestnicy: ..." line (`MeetingNotesPrompt`), so the names are spelled right; that is the only way a participant's name leaves the Mac. The template (`BuiltInMeetingTemplates`: Ogólne, 1:1, Standup, Rozmowa z klientem, Rekrutacja, Wykład / webinar) is picked from the title as it is when the notes are written (the title is editable in the details header, also while recording, `MeetingTitleEditor`; a default "Spotkanie w Zoom, ..." title picks Ogólne) or by the user ("Wygeneruj ponownie", `MeetingNotesRuns`). Citations `[mm:ss]` play the track at that moment.

**Cloud transcript (Pro).** `MeetingCloudTranscription` (`Meetings/Cloud/`) re-encodes each track as AAC in an `.m4a` (`TrackUploadEncoder`, about 15 MB per hour; WAV if the encoder is missing), sends it to ElevenLabs Scribe with word times (`ElevenLabsSTT.transcribeWords`, the user's cloud key, the transcription language and the dictionary as keyterms) and turns the words into segments (`CloudTranscriptSegments`: a new one after a 1 s pause, at a sentence end from 14 s, always at 25 s). Each track's segments replace its live ones (`Database.replaceSegments`), echo is marked again, and the row names the model (`transcriptModel`). A track that fails, or comes back empty where the live pass heard speech, keeps its live lines; the reason goes to `transcriptError`. Both tracks are sent (the mic track too: it is where the user's own names and terms get misheard).

**AI fixes of the transcript (Pro).** `MeetingCorrectionProcessor` with `MeetingTranscriptCorrector`: the lines (no echo) go in batches of up to 80 lines / 7000 characters, three at a time, as `n|text` with the title and a glossary (dictionary + speaker names + the calendar participants, `MeetingTranscriptCorrector.glossary`); the model answers the same numbered lines (`MeetingCorrectionPrompt`). A line is only swapped for its fixed version, never merged, split or dropped, and only when it keeps about the same number of words and characters, so a summary or an added sentence loses that line, not the transcript. Each fixed segment keeps `originalText`; "Przywróć transkrypt sprzed poprawek AI" (`Database.restoreOriginalTranscript`) puts it back. Word times are reused when the count matches, otherwise spread over the old span. `MeetingChat` is the shared non-streaming call of the fixes and the AI notes (reasoning retry, errors as `MeetingSummaryError`). Both use "Model AI do spotkań" (`AppSettings.meetingAIModelID`: empty = the Modele model; a quick pick of Gemini 2.5 Flash Lite as the cheap one).

**Transcript actions.** Above the transcript in the details: where it comes from ("Transkrypt z Maca" / "z chmury", "poprawiony przez AI"), the last failure, and in Pro the "Popraw" menu (`MeetingTranscriptRuns`): "Popraw przez AI", "Transkrybuj ponownie w chmurze" (then the speaker labels again), "Przywróć transkrypt sprzed poprawek AI". "Eksportuj" also has "Usuń tylko nagranie" (confirmed; removes the folder, `hasAudio = false`, transcript and notes stay; off while recording, processing or a transcript run).

**Shortcut.** ⌃⌥⌘M ("Skrót ⌃⌥⌘M" in Ustawienia > Spotkania, on by default) starts a meeting (Spotkania opens first) or ends the one that records. `GlobalShortcut` registers it with Carbon `RegisterEventHotKey`: no event tap and no Accessibility, and the press never reaches the focused app. Registered in `startServices()` only (never in the design preview or the test host); the menu bar items show it.

**Calendar (Free).** "Kalendarz" in Ustawienia > Spotkania (`AppSettings.meetingsCalendar`, off by default) names a recording after the calendar event, keeps the participants and reminds before a call. Sources: `CalendarEventSource` is `EventKitSource` in the app (one `EKEventStore`, reads on a utility queue because a big calendar takes hundreds of milliseconds, `EKEvent` never leaves it; `EKEventStoreChanged` as an `AsyncStream`) and `FixedCalendarSource` in the design preview and the test host (`AppStateOverrides.calendarEvents`, so neither ever touches EventKit). `MeetingCalendar` (`@MainActor @Observable`) holds the `CalendarAccess` (notDetermined / fullAccess / writeOnly / denied / restricted, re-read on every refresh because the user can change it in System Settings) and `upcoming`: plain `CalendarEvent` values (id = `eventIdentifier`, title, start, end, calendar title, up to 50 participant names with the organizer first and the user left out, `callApp` from `CallLinkDetector`) from 15 min ago to 12 h ahead, all-day events left out, refreshed every 5 min, on every calendar change and on demand; empty while the setting is off or access is not full, so nothing from the calendar reaches a recording the user did not ask to link. `CallLinkDetector` names the service only for a real link (a host under meet.google.com, zoom.us / zoom.com, teams.microsoft.com / teams.live.com, webex.com, whereby.com, meet.jit.si or any `jitsi` host label, discord.gg / discord.com, slack.com with `/huddle`, facetime.apple.com) in the URL, the location or the notes; the word "Zoom" in a title is not a link. `CalendarEventMatcher.match` picks the event for a recording that starts now: in progress (start <= now < end + 5 min) or starting within 10 min, preferring a call link, then in progress over upcoming, then the most recently started (the soonest among upcoming), then the shorter, then the id; a start without an event (the menu bar, ⌃⌥⌘M, "Nagraj spotkanie") and the detector's offer go through `MeetingCalendar.currentEvent()`, while the upcoming strip and the reminder pass their own event to `start(event:)`. Occurrences of a recurring event share one `eventIdentifier`, so views key on the whole value and the reminder on id + start. UI: Ustawienia > Spotkania has the "Kalendarz" switch (turning it on asks for access when undecided, turning it off only refreshes; denied / restricted / write-only get a red `ToolStatusLine` with "Otwórz Ustawienia systemowe", `CalendarAccess.openSettings()`), and "Przypominaj przed spotkaniem" with "W chwili startu" / 1 / 2 / 5 min (`meetingsCalendarReminder`, `meetingsCalendarReminderMinutes`; other values read as 1), both greyed while the calendar is off. Spotkania shows `UpcomingMeetingsStrip` under the header and in the empty state: at most 3 events that have not ended, soonest first, "Trwa" for one in progress, the time, the title, the service badge, the participants count (`MeetingParticipantsLabel`: "1 osoba", "2-4 osoby", "5+ osób", the names in a tooltip) and "Nagraj" (disabled while a meeting records or starts), which opens Spotkania and starts the recorder on that event. Reminders: `CalendarReminder` (started in `startServices()`, checks every 30 s) shows "Za 1 min: „Budżet Q4” (Meet). Nagrać notatki?" or "Zaczyna się: ..." with "Nagraj" for an event with a call link whose start is within the setting's minutes (up to 60 s past the start), once per occurrence per launch; quiet while a meeting records or starts, and for an event whose call the detector offered within the last 2 min (`MeetingDetector.lastOfferAt`), which silences that occurrence for good; in the other direction the detector skips its offer for a call that starts within 2 min of a reminder while that event still matches (`MeetingDetector.recentReminder`, `CalendarReminder.lastReminderAt`), so one meeting never gets two "Nagrać?" toasts. Events without a call link get no reminder (in-person meetings start by hand). The reminder never starts a recording by itself. Privacy: only access states and counts are logged (`Log.calendar`), never a title or a name, and the participants leave the Mac only inside the AI notes and AI fixes prompts, when those Pro features run.

**Call detection.** `MeetingDetector` polls `CoreAudioProcesses.usingInput()` every 2 s off the main actor and maps the processes through `MeetingAppCatalog` (Zoom, Teams, Slack, FaceTime, Webex, Discord, Around, Tuple; Chrome, Safari/WebKit, Arc, Edge, Brave, Firefox; each entry has its main bundle ids plus helper prefixes). Browsers count only when a window or tab title names a call service (Meet, Teams, Zoom, Whereby, Jitsi): `BrowserCallWindows` reads the window titles and the tab strip (`AXRadioButton` tabs under an `AXTabGroup`, at most 200 elements per window, the page and lists skipped) and answers `call`, `noCall` or `unknown` (one tab per window, Arc's sidebar, a browser that does not answer); titles are compared, never logged or kept. `DetectionTracker`: a call starts after 5 s of mic use and ends after 45 s without it. Call started while idle: toast "Wygląda na spotkanie w X. Nagrać notatki?" with "Nagraj", or "Wygląda na spotkanie „Budżet Q4” w X..." when a calendar event matches; "Nagraj" opens Spotkania and starts the recorder with that app and event (`recorder.linkedEvent`). A call that started while the last meeting was still finishing is asked about once the recorder is idle. Call end has four signals: (1) 45 s without the mic; (2) the app's process quit (`NSWorkspace.didTerminateApplicationNotification`, only the main bundle id through `MeetingAppCatalog.isMainApp`: Chrome renderers, Teams and WebKit helpers quit mid-call all the time), which ends its call at the next poll; (3) a browser in a call that holds the mic for 30 s (`browserIdleAfter`) while its tab strip shows no call tab (`CallScan.browsersWithoutCallWindow`, only on `noCall`) is dropped from the scan and then waits the usual 45 s (leaving the Meet tab for another tab in the same window is fine: the tab strip still shows Meet; `unknown` browsers keep counting until they release the mic, like M1); (4) the recording's calendar event over for more than 5 min (`eventOverrun`) shortens the wait to 15 s (`overrunEndAfter`) and the toast names the event: "„Budżet Q4” już się skończyło? Kończę notatki za 15 s." (only when some call app held the mic during this recording: a live meeting with no detected app never gets an end toast). The end toast keeps "Nagrywaj dalej"; the stop after 15 s is cancelled by the button, by the app taking the mic again, while another call of the same recording runs, and a manual stop in the countdown is final (`PendingStop` remembers the meeting id). Never records or stops without a visible prompt. The poll reads "Wykrywaj spotkania" every time and starts in `startServices()` (never in the design preview or the test host).

**Storage.** `AppPaths.meetings/<meetingID>/me.caf` and `them.caf`, never under `Recordings/` (the dictation orphan sweep would delete them). Rows: `Meeting` (title, status, duration, app name, notes and note lines, AI notes with template, model and error, speaker names, `hasAudio`, interruptions, transcript model / AI model / error, folded search text, `calendarEventID` and `participants` from the calendar event, stored as `participantsJSON`) and `MeetingSegment` (track, start, end, text, word times, speaker, echo flag, `originalText` before an AI fix). Schema changes stay additive with defaults; `DatabaseMigrationTests` covers them. "Zachowuj nagrania spotkań" (Nie zachowuj, 7 dni, 30 dni, Zawsze) deletes only the audio folder and sets `hasAudio = false`; transcripts and notes stay. It sweeps at launch and after every finished meeting.

**Export.** Markdown (title, date, "Uczestnicy: Anna, Piotr" when the meeting has participants, notes, AI notes, transcript without echo) and an open JSON format `captylo.meeting.v1` (`MeetingExport.formatID`: ids, tracks, segments with word times, notes, AI notes, `participants`, `calendarEventID`), the format later devices and sync will read.

**Clocks.** `MeetingTime.clock` renders `12:34` under an hour and `1:02:03` from one hour; the list, the details, the live bar and the capsule player (`AudioPlayerView.clock`, seconds truncated, not rounded) all use it, so a two-hour meeting never reads `125:00`.

**Pro.** Every Pro check goes through `ProAccess.isPro` / `allows(_:)`. Until accounts exist it is true with the DEBUG switch "Tryb Pro (dev)" (`dev.pro`) or `CAPTYLO_DEV_PRO=1`; the design preview pins it. Free keeps recording, live local transcription, notes, list and export.

**Echo reduction (experimental).** "Redukcja echa (eksperymentalna)" in Ustawienia > Spotkania (`AppSettings.meetingsVoiceProcessing`, off by default) asks the meeting mic's input node for Apple's voice processing (`setVoiceProcessingEnabled(true)` with other-audio ducking at its minimum, `VoiceProcessingSetup`) before the tap is installed; the converter takes the changed native format and the feed still gets 16 kHz mono. An input that refuses it (some Bluetooth outputs, error -10875, at enable or at `engine.start()`) gets the plain engine and the recording always starts; `MeetingMicCapture.isVoiceProcessingActive` says what runs, and `Log.audio` prints "Meeting mic voice processing: on / off / unavailable (...)" once per start and again only when a rebuild (device change, wake) changes the outcome. Read at the meeting's start, so a change applies from the next meeting. `EchoFilter` stays as the second line. Open question for the field: whether VPIO's echo reference on macOS covers other apps' output (Zoom, Meet) or only what Captylo plays.

**Debug.** `--meeting-from-files <me-audio> <them-audio>` runs the pipeline on two files without the mic or the tap and reports the process peak memory; `--compare-models <audio>` runs Parakeet v3 against Parakeet Ultra on one file with timings, peak memory and the word error rate (see the debug flags below). `PeakMemory` reads `task_info` `TASK_VM_INFO` (`phys_footprint` now, `ledger_phys_footprint_peak` since launch, through `task_self_trap()` because the global `mach_task_self_` does not pass Swift 6).

**Known limits.** Echo without headphones is removed from the transcript (`EchoFilter`, 3+ words that mostly repeat an overlapping "Rozmówcy" segment), not cancelled acoustically; short replies like "tak" are kept on purpose. The HAL zero-buffer bug is handled by rebuilding the tap, which can leave a short gap. Browser meetings are detected only with the Accessibility grant and a call service in a window or tab title; Arc exposes no readable tab strip, so an Arc call ends only when the mic is released or the app quits. Slack huddles and FaceTime have no reliable title, so their mic use alone is the signal, and FaceTime audio may run in a system daemon the catalog does not see. The calendar only helps a recording that starts within an event's window; an event without a call link is matched but never reminded about, and the calendar-based end needs a detected call app. Voice processing is a switch, not a promise: outputs that refuse it fall back silently. Diarization needs macOS 15+.

## Windows

The look of every window follows the Dusk Glass design language in the Deep Tide palette: [docs/design/dusk-glass.md](design/dusk-glass.md) (every window is an opaque animated background, by default the Metal "Grainient" gradient, with clear frosted glass panels on it; Manrope + Inter bundled in `Resources/Fonts`; component catalog, widget states, screen-by-screen guidance, the design preview harness).

- Recorder widget: borderless `.nonactivatingPanel`, `canBecomeKey = false`, level `.floating`, all Spaces, bottom center of the screen under the mouse, fixed transparent canvas sized for the expanded state (`RecorderMetrics.canvas`, 448 x 544 pt) with content bottom-anchored; SwiftUI animates inside it. No window shadow (the widget draws its own glows). Clicks on transparent pixels fall through to the app below.
- Widget hover: an `NSTrackingArea` with `.activeAlways` (the panel is never key and the app is usually inactive) plus a 150 ms pointer check while the widget is up; the pointer resting 0.28 s on the widget expands it, leaving it for 0.45 s collapses it, an open row menu keeps it open. The expanded rows go through `RecorderWidgetControls` (`RecorderAppControls`: `AppSettings`, `AudioDevices`, `RecorderCoordinator.togglePause`); a microphone picked mid-take applies from the next take. The "Tryb AI" row, the menu bar submenu of the same name and a click on a mode row in Modele all set `aiEnabled` / `aiActiveModeID` through `RecorderAIModeOptions.select`: "Bez AI" only turns the master switch off, a mode turns it on, so the three surfaces never disagree. The widget menu and the menu bar submenu end with "Edytuj tryby...", which opens the main window on Modele (`RecorderWidgetControls.openModes`, wired in `AppState`). The controller reads the mode when the take stops, so a pick made while recording applies to that take; `RecorderModel.enhancingModeName` captures the running mode when the phase turns `.enhancing` for the status line "Poprawiam z AI · <tryb>". Row menus are plain `NSMenu`s popped from buttons, because a SwiftUI `Menu` in a non-key panel can swallow the first click.
- Toasts: one reusable non-activating panel above the widget (small Dusk Glass capsules).
- Main window: `Window("main")` with sidebar (Pulpit, Spotkania, Historia, Transkrypcja pliku, Słownik, Modele, Ustawienia), ~920 x 640 min. The shell is an `HStack` (`MainSidebar` attached to the left edge + content column), not `NavigationSplitView`, whose system sidebar would paint its own material; Cmd+1...7 and the arrow keys (sidebar focused) switch sections through the `MainRouter`. Dock icon policy switches to `.accessory` when "Ukryj ikonę w Docku" is on and no main window is open.
- Support card (Free plan monetization): a small raised card at the bottom of `MainSidebar`, visible on every section, never in the widget or onboarding. `SupportPromo` picks one message a day (`dayNumber` modulo the options): "Captylo Pro" (opens https://captylo.com/#cennik) and "Postaw kawę twórcy" (opens https://captylo.com/kawa/, a page on our site that holds the Stripe Payment Link, so the link changes without an app release). "x" hides it for 14 days (`AppSettings.supportCardHiddenUntil`). A paid sponsor joins the rotation by setting `SponsorAd.current` in a release; it is compiled in, never fetched, so no network call is made. When the Pro licence exists, hide the card for Pro users.
- Menu bar extra: start/stop dictation, "Nagraj spotkanie" / "Zakończ spotkanie" (⌃⌥⌘M), copy last transcript, microphone and "Tryb AI" submenus, open app, settings, quit. Icon swaps to the `MenuBarIconRecording` template asset while a take or a meeting records (a status item flattens its label, so no overlay dot).

## Debug CLI flags (kept in Release, documented for support)

Run `Captylo.app/Contents/MacOS/Captylo <flag>`; the app runs headless, prints JSON to stdout and exits:

- `--transcribe <audio file> [--ai] [--language pl] [--engine parakeet|cloud]` - full pipeline without the mic (decode → engine → spelling → text processing → optional AI). `--engine` overrides the setting (`parakeet` never reads the Keychain without `--ai`). Output: `{"text","rawText","spelled","enhancedText","modelName","transcriptionMs","enhancementMs"}`; nothing is learned from a debug run.
- `--meeting-from-files <me-audio> <them-audio>` - the meeting pipeline without the mic or the system audio tap (no TCC): both files are decoded to 16 kHz mono and fed from meeting time 0 in 4096-sample chunks, alternately, into a real `MeetingTranscriber` (Parakeet, Silero VAD, echo marks at the end) that saves into an in-memory store. Uses the transcription language setting; the model must be downloaded. With Pro on (`CAPTYLO_DEV_PRO=1` or the dev switch) and macOS 15+ it then labels the speakers of the `them` file like after a real meeting (the offline diarizer downloads its models on first use). Output: `{"ok": true, "segments": [{"track": "me", "start": 1.2, "end": 3.4, "text": "...", "echo": false, "speaker": null}], "transcribed", "language", "speakerTurns", "voices", "ms", "peakMemoryMB"}` (segments as stored, in transcript order; `transcribed` differs from their count only when a save failed; `speakerTurns` and `voices` are null when no diarization ran, and `speaker` stays null with fewer than two voices; `peakMemoryMB` is the process peak footprint, the number to watch in a 2 h soak), or `{"ok": false, "error"}`.
- `--compare-models <audio file> [--reference <txt file>] [--language pl]` - the owner's accuracy and speed check: transcribes the whole file with Parakeet v3 (read from the app's model directory) and then Parakeet Ultra (about 600 MB, downloaded by this tool only into FluidAudio's own cache, `~/Library/Application Support/FluidAudio/Models/parakeet-ultra`, never used by the app), one model loaded at a time, the app's engine untouched. `--language` works like `--transcribe` (default: the transcription language setting). Output: `{"ok": true, "file", "durationSeconds", "language", "reference": <bool>, "models": [{"model": "parakeet-v3", "text", "loadMs", "ms", "rtf", "peakMemoryMB", "memoryDeltaMB", "wer": {"percent", "substitutions", "deletions", "insertions", "words"} | null}, {"model": "parakeet-ultra", ...}], "peakMemoryMB"}`. `wer` (`WordErrorRate`, word Levenshtein on folded, punctuation-free tokens) needs `--reference`; `loadMs` includes the download on the first run; per-model `peakMemoryMB` is sampled every 100 ms while that model loads and runs (the lifetime peak would hide a smaller second model). An unknown language code fails instead of running as auto.
- `--watch-paste <text>` - hidden self-learning check: pastes the text into the focused field like a dictation, watches it like after a dictation and prints the learning memory when the watch ends. Run it with `CAPTYLO_DATA_DIR=<scratch folder>` so the lessons land there.
- `--show-widget <recording|transcribing|enhancing>` - shows the widget with fake levels and sample live text and stays up until killed (for screenshots with `screencapture -x`).
- `--check` - prints permission states, model status, selected device, hotkey, the data paths, the active AI mode and the history row count. It reads the Keychain, so an ad-hoc Debug build can block on an ACL prompt.

`CAPTYLO_DATA_DIR=<folder>` points `AppPaths` (store, dictionary, recordings) at another folder for support and for migration checks on a copy of the store. Settings still come from the real defaults domain.
- `--reset-onboarding` - clears onboarding progress.
- `--ax-probe [--show-text]` - hidden self-learning spike tool: once a second prints a one-line JSON when the focused text field changes (bundle id, role, subrole, length, readable, selection). Sets `AXManualAccessibility` once per frontmost app so Electron apps expose their fields. The field text (last 80 characters) is printed only with `--show-text`. Runs until killed; needs the Accessibility grant. Findings go to [docs/reference/ax-coverage.md](reference/ax-coverage.md).
- `--open-section <pulpit|spotkania|historia|plik|slownik|modele|ustawienia>` - hidden screenshot helper: a normal GUI launch (services, tap, menu bar) that skips the onboarding and opens the main window on that section.
- `--design-preview <target>` - hidden design helper: one screen (widget state, onboarding step, main section or `glass-gallery`) on fake services built through `AppStateOverrides` (in-memory store with sample history and three sample meetings, Pro pinned on unless `CAPTYLO_PREVIEW_FREE=1`, defaults suite `com.captylo.app.design-preview` wiped at start, temp dictionary, seeded key store, pinned Parakeet "ready", a pinned "ready" voice detector, Accessibility, and a `FixedCalendarSource` that is empty unless `CAPTYLO_PREVIEW_CALENDAR=1` seeds three invented events; EventKit is never created). No services, no hotkey tap, no menu bar item, never activates the app. Prints `WINDOW_FRAME=x,y,w,h` and `WINDOW_ID=<n>` when the window is up (optional `CAPTYLO_PREVIEW_BACKDROP=white|dark|<image>` puts a backdrop window behind it) and runs until killed; unknown target = JSON error, exit 64. Driven by `scripts/snap.sh <target> <out.png>` (see dusk-glass.md).

When the app is the unit-test host (`XCTestConfigurationFilePath` set) it skips `startServices()` and the onboarding, so `make test` never installs a second hotkey tap. It builds `AppState` on `AppStateOverrides.testHost()` (in-memory store, temp dictionary, wiped `com.captylo.app.test-host` defaults suite), so a schema change can never migrate the user's store while a real Captylo is running.

Schema changes stay additive and optional (or defaulted), so SwiftData migrates the store in place without a `VersionedSchema`; `DatabaseMigrationTests` keeps a frozen copy of the previous schema and checks both the upgrade and a rollback to it.

## Build and install

`make gen` (XcodeGen), `make build` (Debug, `.local-build/`), `make test`, `make release` (Release, ad-hoc signed, copied to `~/Downloads/Captylo.app`), `make install` (also copies to `/Applications`), `make check` (Debug binary `--check`), `make reset-tcc` (resets the `com.captylo.app` grants). The first Parakeet load of a new binary takes ~20-30 s (Core ML specialization); later loads ~0.3 s.
